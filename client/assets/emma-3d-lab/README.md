## ไฟล์และโครงสร้าง

- `emma.blend`: ต้นฉบับแก้ไขได้ มี mesh, วัสดุ, armature, actions, กล้องและไฟสำหรับตรวจงาน
- `emma.glb`: โมเดลสำหรับเว็บ บรรจุวัสดุ skin weights และแอนิเมชัน ไม่มี dependency ภาพภายนอก
- `emma-light-68k.glb`: ตัวเดียวกันที่กริดหยาบกว่า — **เลิกใช้แล้ว (29 ก.ย. 2026)** หน้าเว็บกลับไปโหลด `emma.glb` เพราะตัวนี้ทำขอบแถบโครเมียมหัวขาด (ดู "จำนวน polygon")
- `model-audit.json`: ผลตรวจจาก Blender ของ build ล่าสุด
- `index.html`, `viewer.js`: หน้าตรวจโมเดล Three.js แยก ใช้ static assets route เดิมของแอป ไม่เชื่อมไมโครโฟนหรือโมเดลเสียง
- `vendor/`: Three.js 0.180.0 พร้อม MIT license และข้อมูลที่มาของแพ็กเกจ ใช้โมดูลจากเครื่อง ไม่โหลด CDN ระหว่างเปิดหน้า

โครงกระดูก 40 ชิ้น: Root, Body, Neck, Head และข้างละ Shoulder, Forearm, Wrist, Palm, นิ้วชี้/กลาง/นาง/ก้อยนิ้วละ 3 ข้อ กับนิ้วโป้ง 2 ข้อ มือแต่ละข้างเป็น mesh เชื่อมต่อชิ้นเดียว ผูกกับกระดูกโดยมีน้ำหนักรวมต่อ vertex เท่ากับ 1 ใช้ linear blend skinning แบบเดียวกับไฟล์ GLB

Form Study 03 ใช้แบบแยกชิ้นใน `../emma-reference-study/` ปรับรูปทรงครบตัว โดยแยก generator เป็น `scripts/emma_sculpt_body.py` สำหรับหัว/ตา/คอ/ลำตัว และ `scripts/emma_sculpt_hands.py` สำหรับเบ้าไหล่/ถุงมือ/กระดูกนิ้ว มือชุดสี่นิ้วเดิม (ฝ่ามืออวบชิ้นเดียว นิ้วโป้งฝั่งใน แบ–กำและโบกด้วย mesh เดิม) ยังอยู่ในไฟล์แต่ถูกปิดด้วย `ARM_STYLE`

ไหล่เป็นลูกบอลโครเมียมลูกเดียวในเบ้าดำ ต่อด้วยปลอกข้อมือเรียบหนึ่งชิ้นตามแบบ (23 ก.ย. 2026: กระบอกสองท่อนมีร่องปลายซ้อนแหวนสองวง เห็นใน viewer เป็นลายทางขาวดำ) โคนแขนสีขาวต่อกับมือเป็นผิวเดียว นิ้วสั้นลง ~22% และอวบขึ้นให้ยาวราวสองเท่าของความกว้างตามถุงมือในแบบ น้ำหนัก Forearm ถูกจำกัดบริเวณสะพานข้อมือเพื่อไม่ดึงผิวนิ้วโป้งตามการพลิกแขน การสร้างคีย์เฟรมจัด quaternion ให้อยู่ฝั่งเครื่องหมายเดียวกัน ป้องกันการหมุนอ้อมผิดทางระหว่างยกและลดมือ

ทั้งตัวถูกปั้นใหม่ตามแผ่น CHARACTER CONCEPT (`../emma/emma-character-concept-v1.png`) เมื่อ 23 ก.ย. 2026 โดยวัดจากแผง HEAD/TORSO/ARMS-HANDS/FULL CHARACTER VIEWS ก่อนแก้ทุกค่า หัวเป็นเปลือกมุกลึกเกือบทรงกลม (RZ 1.154 · ครึ่งล่างเป็น superellipse ตามที่แบบดึงคางขึ้น) มีแถบโครเมียมเส้นเดียวพาดด้านข้าง กว้าง .36 เอียง -.03 ยอดแถบเอียงมาทางหน้า มองจากหน้าเห็นเป็นขอบบาง ตาเป็นเสี้ยวปลายมน W wave ยกตามพิกัดที่วัดจาก head_front ลำตัวยอดบนเป็นโดมให้ปลอกคอนั่ง หนา .88 ของความกว้าง **ไม่มีคอ** หัวนั่งในโดมของลำตัวโดยตรงตามแผ่นสเปก (23 ก.ย. 2026 — ชุดปลอกคอถูกลบทั้งหมด ไม่ใช่ย่อลง) **แขนเป็นครีบแบน ไม่มีไหล่ ไม่มีข้อต่อ (23 ก.ย. 2026)** เจ้าของดู build ที่ทำตาม character sheet แล้วบอกว่า "ตั้งแต่ส่วนไหล่ไม่เหมือนสักอันเลย" จึงถอดชุดไหล่–ข้อมือ–ถุงมือสี่นิ้วออกทั้งหมด แล้วส่งภาพใหม่เป็นลำตัวที่มีแขนกลมมนสองข้าง จากนั้นลองแขนครีบกลม ถอดออก แล้วเจ้าของส่งแผ่น **EMMA — 3D MODELING REFERENCE** ที่มีขนาดกำกับ จึงปั้นแขนใหม่ตามนั้น (`build_fin_arms`): อัลมอนด์แบนสมมาตร เอียง 40° จากแนวดิ่ง หนา .37 ของความกว้าง สร้างด้วย sweep ตาม `FIN_PROFILE` (โปรไฟล์ครึ่งวงกลม = ellipsoid เป๊ะ) เคยลองเปลี่ยนเป็นทรงหยดน้ำตามภาพหุ่นคู่หูอีกชุดสามรอบ เจ้าของตัดสินว่าแย่กว่าเดิมจึงย้อนกลับ กลไก sweep ยังอยู่ ถ้าจะลองหยดน้ำใหม่แค่ย้ายจุดสูงสุดใน `FIN_PROFILE` โคนซ้อนอยู่ในลำตัวจึงไม่มีข้อต่อให้ต้องวาด ความกว้างรวม/ความกว้างลำตัว = 1.918 (สเปก 1.28/0.68 = 1.882) ตอนนี้ `ARM_STYLE = "fin"` ใน `build-emma-3d-lab.py` เลือกได้สี่ค่า: `fin` (ที่ใช้อยู่) · `flipper` (ครีบกลม) · `glove` (ชุดสี่นิ้วเดิม) · `None` (ไม่มีแขน) **ไม่มีค่าไหนถูกลบทิ้ง** โค้ดทั้งสองชุดยังอยู่ครบใน `emma_sculpt_hands.py` `scripts/verify-emma-3d-lab.py` มี `ARM_STYLE` กับ `BONES_BY_STYLE` ของตัวเองที่ต้องแก้ให้ตรงกันเสมอ (glove 56 / fin 6 / flipper 6 / None 4 กระดูก) และถ้ากลับไปใช้ `glove` ต้องคืน clip `wave`/`grip` ปุ่มใน index.html และบล็อกเทสต์ถุงมือจาก git history ด้วย เทสต์เขียนให้ตรงกับโมเดลที่สร้างจริงเท่านั้น ไม่เขียนเผื่อ — เทสต์ที่ถามหาถุงมือในโมเดลที่ไม่มีถุงมือจะเขียวเพราะ "เครื่องไม่มีของ" ไม่ใช่เพราะโค้ดถูก

แสงใน viewer ใช้ softbox สะท้อนบนฉากมืดพร้อม environment ขนาด 512 และ glow เฉพาะวัสดุเรืองแสงจากการเรนเดอร์โมเดลจริง วัตถุทึบยังบังแสงใน pass นี้ได้ จึงไม่มีไฟหน้าอกส่องทะลุด้านหลัง ปุ่ม “เทียบแบบ” เปิดมุมเฉียงเล็กน้อย ส่วน “หน้าตรง” ใช้ตรวจความสมมาตร แสงเรนเดอร์ Blender และ viewer เป็นคนละชุด จึงควรเทียบสีด้วยภาพจาก viewer ที่จะใช้งานจริง

มี 2 clips: `idle`, `look` (ส่วน `wave`, `grip` เป็นท่ามือ กลับมาพร้อม `ARM_STYLE = "glove"`) ท่าพักต้นและท้ายสอดคล้องกัน ใน viewer เก็บท่าที่เห็นอยู่จริงก่อนเปลี่ยน clip แล้วผสม quaternion/ตำแหน่งเข้าท่าใหม่ 0.65 วินาที หากเปลี่ยนกลางทางจะเริ่มจากท่าปัจจุบัน การสุ่มตัวอย่างแอนิเมชันใช้ hierarchy แยกเพื่อไม่เขียนทับค่าที่ AnimationMixer เก็บไว้

### จำนวน polygon (25 ก.ย. 2026)

**29 ก.ย. 2026: หน้าเว็บกลับไปโหลด `emma.glb`** (25–29 ก.ย. เคยโหลด `emma-light-68k.glb`) เจ้าของหมุนหุ่นแล้วเห็น
"ขอบที่ดูขาดๆ ตรงรอยต่อหัว" — วัดแล้ว: `EMMA_LOD_ONLY` มี `Head` ซึ่งตรงกับ `Head / pearl shell` (mesh `Sphere`) และ `_lod_for`
ทำงานใน `ellipsoid()` ด้วย ไม่ใช่แค่ `patch()` → เปลือกหัวเหลือ 1,628 จาก 20,224 สามเหลี่ยม · หน้าแบนของเปลือกหยาบยุบเข้าไป
สูงสุด ~.007 ลึกกว่าขอบแถบโครเมียมที่ฝังไว้ .004 (`BAND_BASE .996`) แถบจึงโผล่กลางหน้าและจมที่ทุก vertex = ขอบหยักเป็นฟันเลื่อย
(แถบเองกริด 256×12 เท่ากันทั้งสองไฟล์) · สลับ**เฉพาะเปลือก**ระหว่างสองไฟล์ รอยขาดย้ายตาม · **ที่หลุดการตรวจ:** ทุกภาพเทียบ
เป็นมุมหน้าตรง ซึ่งเห็นแถบเป็นขอบบาง และค่าเฉลี่ยทั้งภาพ ~1/255 แยกไม่ออก — ตัวเบาต่อไปต้องเทียบจากด้านข้างและด้านบน
และดูบริเวณรอยต่อ ไม่ใช่ค่าเฉลี่ยทั้งภาพ · ทางที่ยังไม่ได้ลอง: build ใหม่โดยเอา `Head` ออกจาก `EMMA_LOD_ONLY` (~+18.6k สามเหลี่ยม)

| ไฟล์ | สามเหลี่ยม | ขนาด | draw call |
|---|---|---|---|
| `emma.glb` (ต้นฉบับที่อนุมัติ · **ที่ใช้จริง**) | 162,380 | 5.13 MB | 22 |
| `emma-light-68k.glb` (เลิกใช้ — ขอบหัวขาด) | 68,322 | 2.38 MB | 22 |

สร้างตัวเบาด้วย knob ที่มีอยู่แล้ว ไม่มีขั้นตอน decimate แยก:

```powershell

```

`EMMA_LOD_ONLY` จำกัดการลดของ `patch()` ไว้กับชิ้นที่ยังมีรายละเอียดต้องรักษา
ส่วน `EMMA_SCULPT_LOD` คุมกริดของลำตัว/ตา กติกาสองข้อที่จ่ายด้วยการวัดจริง:

- **ลดแบบเหมารวมทั้งตัวห้ามใช้** `EMMA_LOD` อย่างเดียวที่ 62% ให้ผิวลำตัวเป็นจุดด่าง
  (`.tmp/stage-design-20260924/poly-light-broken.png`) — ชิ้นที่บางอยู่แล้วทนการลดไม่ได้
- **ต้องเช็คชื่อ node หลัง build ทุกครั้ง** renderer หาปุ่มหน้าอกจากชื่อ `Chest / ...`
  หาไฟเรืองแสงจากวัสดุ `White light` และหากระดูกจากชื่อ ถ้าหายไปหน้าเว็บยัง**เรนเดอร์ปกติ**
  แค่กดเปลี่ยนโหมดไม่ได้ — `tests/test_voice_preview_page.py` อ่าน GLB ที่หน้าเว็บโหลดจริงมาตรวจให้

**ผลวัดบน GPU จริง** (RTX 5060, canvas 900×1250, ค่ากลางของเวลาต่อเฟรม):

| | glow เปิด | glow ปิด |
|---|---|---|
| 162k | 3.30 ms | 2.80 ms |
| 68k | 2.60 ms | 2.50 ms |

รอบเรืองแสงส่ง**ทั้งโมเดลเข้า GPU รอบที่สอง** (ดู `renderScene`) ตัวเลขจึงไม่แยกกัน:

(300+ fps) ตัวเลขที่ต้องไปวัดจริงคือจอหุ่น ซึ่งยังไม่ได้วัด — `?glow=0` ในหน้า
stage-lab ปิดรอบเรืองแสงไว้ให้วัดแยกได้ ส่วนต่างของภาพระหว่างสองไฟล์บนหน้าจริง
วัดได้ 1.05/255 โดยเฉลี่ย และอยู่บนขอบไฮไลต์โครเมียมล้วน

ตัด mask จากแผงต้นแบบ (กันตัวอักษร FRONT/SIDE ปน) เทียบกับ alpha ของ render จัดสเกลด้วยความกว้างหัว ได้ IoU ระยะขอบ โปรไฟล์ความกว้าง 24 แถว ภาพ overlay/difference และ contact sheet ใน `build/reference-compare/` ค่าล่าสุดอยู่ใน CHANGELOG.md ส่วน `head_side` ต่ำผิดปกติเพราะตัวตัดหัว-คอของเครื่องมือเอง ไม่ใช่รูปทรง (ใส่ `--render-box` ตรงๆ ได้ .964)

## สถานะและขอบเขต

เป็น **ต้นแบบรูปทรงและ rig ที่ยังไม่ได้อนุมัติหน้าตา** วัสดุและสัดส่วนใบหน้า/มือยังไม่เหมือนภาพอ้างอิงทั้งหมด หัวเป็นโดมทรงรี ลำตัวมีขอบโครเมียมและแผ่นขาวหน้า–หลัง มือมีครบห้านิ้ว แต่ยังต้องปรับผิวข้อพับและท่าทางด้วยงาน modeling/animation เพิ่มเติม

ยังไม่มี rig ควบคุมสีหน้า/ปากพูด ไม่มี prop สำหรับจับแว่น ไม่มีระบบหลบการทะลุอัตโนมัติ และยังไม่ได้เชื่อมกับสถานะสนทนา การตรวจความต่อเนื่องเชิงตัวเลขไม่ใช่การรับรองว่าท่าทางสมจริงหรือไม่มีชิ้นส่วนชนกันทุกกรณี Rive และหน้าเสียง production ไม่ถูกแทนที่
