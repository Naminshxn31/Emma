# ข้อมูลในโปรเจกต์

ไฟล์ใน `data/` ไม่ได้มีสถานะเท่ากันทั้งหมด บางไฟล์เป็นข้อมูลที่คนดูแลแก้ บางไฟล์สร้างจากไฟล์อื่น บางไฟล์เป็นตัวอย่าง และบางโฟลเดอร์เป็นข้อมูลส่วนตัวที่เกิดตอนระบบทำงาน

ทะเบียนกลางอยู่ที่ [`registry/source_registry.json`](registry/source_registry.json) และตรวจได้ด้วย:

```powershell
python scripts/audit_data_sources.py
```

สัญญาว่าไฟล์ใดต้องอยู่ใน Git และไฟล์ใดต้องเตรียมจากภายนอก พร้อมวิธีตรวจ `ci` / `runtime` / `full` อยู่ที่ [Source Availability & CI Contract](../docs/source-availability-contract.md) สำหรับ clean checkout ใช้ `python scripts/audit_data_sources.py --mode ci`; ก่อนเปิดจอนำเสนอจริงใช้ `--mode runtime` เพื่อตรวจ asset ภายนอกและ SHA-256

หลักที่ใช้คือ:

1. ราคา โปรโมชั่น ขนาดห้อง และคำสัญญาเชิงพาณิชย์ต้องมาจากแหล่งที่ทะเบียนอนุญาตและมีสถานะอนุมัติครบ
2. `project_knowledge.json` มีไว้ช่วยหาและเลือกสไลด์ ไม่ใช่หลักฐานยืนยันข้อเท็จจริง
3. `slides/index.json` เป็นคำบรรยายและเนื้อหานำเสนอ จึงห้ามใช้แทนราคา โปรโมชั่น หรือสถานะยูนิต
4. `units.sample.json` เป็นข้อมูลสมมติและต้องคงป้ายตัวอย่างเสมอ
5. `personal-docs/`, `memory.json`, `reminders.json`, `faces/` และ `logs/` เป็นข้อมูลส่วนตัว จึงถูก ignore และห้ามยกเป็นข้อมูลส่วนกลางของโครงการ
6. แผนที่ห้องขายและผังหุ่นต้องแยกค่าที่วัดหรือยืนยันแล้วออกจากค่าที่อนุมาน

ข้อมูลที่ระบุได้ว่าเป็น Embassy World อยู่ใต้ `projects/embassy_world/` แยกเป็น `facts/`, `routing/`, `presentations/slides/` และ `sales/` ข้อมูลสไลด์ 15 รายการที่เป็นโครงการอื่นหรือประวัติผู้พัฒนาอยู่ใน `review/other_projects/` เพื่อรอจำแนก ไม่ถูกค้นใน session ปกติ ภาพเก่า 59 ไฟล์ที่ไม่ได้อยู่ในดัชนี พร้อมไฟล์สำรองและแคชเดิม อยู่ที่ `review/unindexed_slides/` โดยไม่ถูกลบหรือใช้ตอบลูกค้า

`source_id` และ `project_id` ในไฟล์ JSON ต้องตรงกับทะเบียน ระบบเสียงเครื่องนี้รองรับ `embassy_world` โครงการเดียวต่อ server; การขยายไปโครงการอื่นต้องเพิ่มแหล่งข้อมูลที่จำแนกแล้วและทดสอบขอบเขตก่อน ห้ามตั้งชื่อโฟลเดอร์ให้ข้อมูลที่ยังไม่รู้เจ้าของหรือถือว่าการย้ายไฟล์คือการอนุมัติเนื้อหา

ยังไม่ได้ย้าย `documents/` (catalogue และ PDF ต้องตรวจเจ้าของเนื้อหา), `personal-docs/` (เอกสารส่วนตัวที่ไม่ track), `showroom/` (ข้อมูลพื้นที่/ฮาร์ดแวร์), `units.sample.json` (ข้อมูลตัวอย่าง) และข้อมูลทดสอบ เพราะการย้ายไปใต้โครงการโดยไม่มีหลักฐานจะติดป้ายผิด ส่วน `mydocs` ในโหมดห้องขายอ่านได้เฉพาะโฟลเดอร์ชื่อโครงการที่ server กำหนด

เครื่องอื่นที่มี `.env` ของตนเองต้องตรวจ `SLIDES_DIR`, `PROJECT_KNOWLEDGE_FILE`, `UNITS_FILE` และ `PROJECT_ID` ก่อนเปิดบริการ เพราะค่าที่กำหนดเองจะทับค่า default ใหม่; ดูตัวอย่าง path ที่ `.env.example` และใช้ `python scripts/audit_data_sources.py` หลังย้ายข้อมูล

เมื่อเพิ่มแหล่งข้อมูลใหม่ ให้เพิ่มรายการในทะเบียนก่อนระบุว่าใครเป็นเจ้าของข้อมูล ใช้ตอบอะไรได้ อายุข้อมูลเท่าไร และถ้าหายต้องตอบอย่างไร จากนั้นเพิ่มการตรวจใน `scripts/audit_data_sources.py` หากแหล่งนั้นมีเงื่อนไขพิเศษ
