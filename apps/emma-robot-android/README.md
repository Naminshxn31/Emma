# Emma Robot Android

แอป Android หลักสำหรับติดตั้งและทำงานบนหุ่น Astronaut/ZC-3588A โดยตรง แยกจากเว็บเซิร์ฟเวอร์ของ `condo-voice` และแยกจากเครื่องมือทดลอง Xbox Direct

## ขอบเขตรุ่น 0.1

- จอแนวตั้ง 1080×1920 สำหรับจอกลางของหุ่น
- จอย Xbox ที่จับคู่กับ Android ของหุ่น สั่งฐานล้อผ่าน Slamware ภายในโดยไม่ผ่านคอม
- แขนและนิ้วผ่านบอร์ด CH340 `1a86:7523` พร้อมค้นหา `/dev/ttyUSB*` อัตโนมัติ
- เล่นกลุ่มท่า 1–26, คืนท่าพักกลุ่ม 99 และสร้างร่างท่าแบบหลายคีย์เฟรมในแอป
- แสดงเฉพาะผังช่องที่มีหลักฐาน: ช่อง 5 = แขน, 7 = หันหัว, 8 = ก้ม/เงย; ช่องอื่นยังแสดงเป็นเลข
- เริ่มทุกครั้งโดยล็อกฐานล้อ และไม่สั่งแขนเพียงเพราะเปิดแอป
- เมื่อกล้องตรวจพบหน้าและเซิร์ฟเวอร์ส่งคำทักทาย หน้า Emma ขอให้แอปเล่นกลุ่ม 6 หนึ่งรอบผ่าน Android SDK ซึ่งเจ้าของยืนยันว่าเป็นท่าจับมือ; ต้องเปิดสวิตช์แขน/กลุ่มท่า/ทักทาย/การเคลื่อนที่บนเซิร์ฟเวอร์ และแอปต้องอยู่ด้านหน้า

## ปุ่มหลัก

- `A` เปิดควบคุมฐานล้อ และใช้ก้านซ้ายขับ
- `B` หยุดและล็อกฐานล้อ พร้อมส่ง `#STOP` ให้แขนถ้าเชื่อมอยู่
- `X` เชื่อมบอร์ดแขน หลังแอปหยุด Aobo เพื่อคืนพอร์ต CH340
- D-pad ซ้าย/ขวา เลือกกลุ่มท่า และ `Y` เล่นหนึ่งรอบ

`#STOP` เป็นคำสั่งระดับบอร์ดและยังไม่ใช่หลักฐานว่ามอเตอร์หยุดจริง ปุ่มหยุดด้านหลังหุ่นและสวิตช์ไฟหลักยังเป็นทางหยุดทางกายภาพ

## หน้า Emma (จอลูกค้า) และการตั้งค่าเซิร์ฟเวอร์

จอเริ่มต้นคือหน้า Emma (`/preview?app=1&cam=1` ของเซิร์ฟเวอร์) หน้าควบคุมฐานล้อ/แขนซ่อนอยู่: กดค้างมุม**ซ้ายบน** 3 วินาที หรือกด START ค้างแล้วกด SELECT บนจอย

- **ครั้งแรก** (ยังไม่มี token) หน้าตั้งค่าขึ้นเอง ใส่ที่อยู่เซิร์ฟเวอร์ + `WS_TOKEN`
- **ตั้งค่าแล้วจะไม่มีปุ่มฟันเฟืองบนจอลูกค้าเลย ทุกบิลด์** (เดิมบิลด์ debug ยังโชว์อยู่ และหุ่นใช้บิลด์ debug) —
  พนักงานเข้าหน้าตั้งค่าด้วยการ**กดค้างมุมขวาบน 5 วินาที** (ขยับนิ้วออกจากมุม ยกนิ้ว หรือแตะนิ้วที่สอง = ยกเลิก)
- **token ผูกกับเซิร์ฟเวอร์ที่ใส่คู่กัน** และไม่ถูกเติมกลับลงช่องเมื่อเปิดหน้าตั้งค่า:
  - ช่อง token ว่าง + เซิร์ฟเวอร์เดิม = ใช้ token เดิม
  - ช่อง token ว่าง + เซิร์ฟเวอร์ใหม่ = **ปฏิเสธ ไม่บันทึกอะไร** Emma ยังต่อเซิร์ฟเวอร์เดิม — ใส่ token ของเซิร์ฟเวอร์ใหม่ก่อน
  - เทียบเซิร์ฟเวอร์แบบ origin มาตรฐาน: ตัวพิมพ์เล็ก/ใหญ่ของชื่อเครื่อง และ `:443` ไม่นับว่าเปลี่ยน
  - ติดตั้งทับ APK รุ่นก่อน: token ที่เก็บไว้ถูกผูกกับเซิร์ฟเวอร์ที่เก็บคู่กันให้เอง ไม่ต้องตั้งใหม่

**ตั้งค่าผ่าน adb (เฉพาะบิลด์ debug)**:
`adb shell am start -n com.emma.robot.control/.MainActivity --es server_url https://<เครื่อง>:8001 --es ws_token <token>`
ส่งมาคู่กัน = token ผูกกับเซิร์ฟเวอร์นั้น · ส่ง `server_url` อย่างเดียวไป origin ใหม่ = **token เดิมถูกลบ** หน้าเดิมถูกปิด แล้วหน้าตั้งค่าขึ้นมาขอ token
(กิจกรรมหลักของแอปเปิดให้แอปอื่นเรียกได้ จึงห้ามให้ extras พา token เดิมไปเครื่องอื่น) · ส่ง `server_url` ที่ไม่ผ่าน (เช่น http ไปเครื่องอื่น)
= ไม่รับทั้งคำสั่ง · บิลด์ release ไม่อ่าน extras เลย · WebContents debugging เปิดเฉพาะ debug

**สิทธิ์ไมค์/กล้อง**: ขอพร้อมกันในหน้าต่างเดียว · หน้าต่างขอสิทธิ์ของแอปเอง**ไม่ตัดสายและไม่ปิดการสแกนใบหน้า**อีกแล้ว
(เดิมหน้าต่างนี้ทำให้แอป "พัก" แล้วหน้าเว็บปิดตัวเอง) · ถ้าปฏิเสธ แอปจะไม่ถามซ้ำจนกว่าจะเปิดแอปใหม่ — จะเปิดสิทธิ์ทีหลังให้ไปที่
Settings › Apps › Emma Robot › Permissions (เดิมกล้องที่ถูกปฏิเสธถูกถามซ้ำทุก 10 วิ และแต่ละครั้งตัดสายที่คุยอยู่)

## ท่าทางด้วยเสียง + นำทาง (9 ต.ค. 2026 — ยังไม่ได้ทดสอบบนหุ่น)

ตามแบบ `docs/emma-body-nav-design-2026-10-08.md` §2b/§2c — **ทุกอย่างปิดเป็นค่าเริ่มต้น** ทั้งที่หุ่นและที่เซิร์ฟเวอร์

- **สะพานจากหน้าเว็บ** (`window.prompt`, ไวยากรณ์ปิด): `emma-body:list|status|stop|<id>`, `emma-nav:places|status|stop`,
  `emma-nav:go:<place>:<tap|voice>`, `emma-face:token` และ `emma-arm:greet:6` เดิม — ทุกข้อความผ่านด่านเดียวกับท่าจับมือเดิม
  (origin ที่เชื่อถือ + `/preview` + `app=1`) ไม่ผ่าน = `bad_request` และไม่มีอะไรทำงาน · `EmmaFace` ตรวจแค่รูปร่าง id
  ส่วน `MainActivity` ตรวจกับตารางของตัวเอง (ตรวจสองชั้น)
- **ท่าทาง** (`BodyGestures` + `BodyController`): ใช้ได้ตอนนี้คือ `handshake` (กลุ่ม 6), `greet_arm` (กลุ่ม 3), `rest` (กลุ่ม 99) ·
  `head_center`/`head_down`/`nod` ใช้แค่ค่าที่เจ้าของวัดไว้ (`#8P1540`, +40) และต้องเปิด "เปิดท่าที่ยังไม่ทดสอบทิศ" ก่อน ·
  ที่เหลือ `needs_mapping` จนกว่าจะบันทึกท่าจากสตูดิโอ ("บันทึกร่างนี้เป็นท่า…" — ต้องกด "เล่นร่างท่า" ดูก่อน, ช่อง 7/8 ได้แค่ 1460–1540)
  · ทีละท่า, พัก 3 วิ, ไม่เกิน 6 ท่า/นาที, ห้ามขยับระหว่างหุ่นเดิน, ท่าแขนจบด้วยกลุ่ม 99 เสมอ
- **นำทาง** (`NavLauncher`): สั่ง `su 0 sh -c "… emma_nav.py go <place> --origin … --run-id <hex32> --tether"`
  (ติดตั้ง/deploy จากคอมด้วย `scripts/robot_python.py` ก่อน) แอปไม่เคยส่งเลขขั้นเส้นทาง · ก่อนเดินเก็บแขน (กลุ่ม 99) และต้องได้ `#AGF`
  · ping ทุก 1 วิ, เช็กสถานะทุก 5 วิ (เห็นการเดินที่สั่งจากคอมด้วย), `emma_nav.py reap` ทุกครั้งที่เปิดแอป
- **แถบแดง "■ หยุดหุ่น" ของแอปเอง** (ไม่ใช่ของหน้าเว็บ) โผล่ระหว่างเดิน/ทำท่า · การหยุดทุกทาง (แถบแดง, B, ปุ่มหยุดหน้าควบคุม,
  แอปพัก/เสียโฟกัส/ปิด, เปิดหน้าควบคุม, คำสั่งหยุดจากหน้าเว็บ) หยุด**ทั้งการเดินและแขน** และล็อก 60 วิ (ล้างได้ที่หน้าควบคุม) ·
  ลำดับหยุดการเดิน: ยกเลิกคิว → `stop` ทาง tether → `emma_nav.py stop` → 2 วิแล้ว `kill -9` → `DELETE /actions/:current`
- **หน้าควบคุม** เพิ่ม: สวิตช์ท่าทางเสียง / ท่าที่ยังไม่ทดสอบทิศ / นำทาง / เก็บแขนก่อนเดิน, อนุญาตช่องสำหรับท่าเสียง (ค่าเริ่มต้น 5, 7, 8),
  ล้างการล็อก, "ตรวจระบบนำทาง (ไม่ขยับ)" และช่อง face token (คู่กับ `ROBOT_FACE_TOKEN` ของเซิร์ฟเวอร์)

ทางหยุดที่แน่นอนยังคือปุ่มหยุดฉุกเฉินด้านหลังและสวิตช์ไฟหลัก — `stopAll` ยังไม่มีหลักฐานว่าหยุดแขนกลางทางได้จริง (bench B3)

## สร้าง APK

ต้องมี JDK 17 และ Android SDK 34 จากนั้นรัน `gradlew.bat --no-daemon assembleDebug` ในโฟลเดอร์นี้ APK จะอยู่ที่ `app/build/outputs/apk/debug/app-debug.apk`

หุ่นใช้ APK debug ตัวนี้ (รีโปยังไม่มี release signing) ด่านที่อยู่บนจอลูกค้า — ไม่มีฟันเฟือง, token ไปได้แค่เซิร์ฟเวอร์ของมัน — จึงไม่ผูกกับชนิดบิลด์

ไลบรารี `aoborobotsdk-v2.1.2.aar` มาจากชุดพัฒนาที่เจ้าของหุ่นให้ไว้ และเก็บเฉพาะในแอปนี้เพื่อให้สร้าง APK ได้โดยไม่พึ่งโฟลเดอร์ทดลอง
