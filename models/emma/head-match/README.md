# EMMA — ตรวจทรงหัวตามภาพต้นฉบับ

ทำเฉพาะ **Phase A–D: หัว** ตามไฟล์แนบของผู้ใช้และ [CODEX_MODEL_SPEC.md](../../../CODEX_MODEL_SPEC.md) สถานะ **draft / ยังไม่อนุมัติทรง** งานทดลองทั้งตัวเดิมพักไว้ ไม่ใช้เป็นข้อมูลรูปทรงของไฟล์นี้

เปิด [ภาพเปรียบเทียบหน้า–หลัง](validation/head-comparison.png) และ [ไฟล์ Blender](EMMA_HEAD_MATCH.blend) ได้โดยตรง ไฟล์นี้ไม่มี armature, action, ลำตัว หรือมือ และไม่ได้ส่งออก GLB/FBX

## หลักฐานและขนาด

ต้นฉบับที่วัดคือ `client/assets/emma/emma-pose-library-reference-v1.png` ขนาด 1501 × 1008 พิกเซล ตรวจ SHA-256 ก่อนสร้างทุกครั้ง พิกัด Bézier และเส้นที่สุ่มตัวอย่างจากภาพอยู่ใน `scripts/emma_head_reference_data.py`; ภาพพร้อมเส้นที่วัดอยู่ใน `references/*_trace.png` ไม่ใช้ภาพ draft เป็นเป้าหมาย

[measurements.json](measurements.json) เก็บขนาดหัวหน้า 1.0 หน่วย ความสูงประมาณ 0.968 หน่วย พิกัดต้นฉบับ วิธีจัดแนว และความไม่แน่นอน ค่า `head_depth` เป็น `null` เพราะยังไม่มีภาพด้านข้าง 90° ที่สอบเทียบได้ ความลึก 0.68 ใน `construction_assumptions` เป็นค่าขึ้นทรงชั่วคราวแยกต่างหาก ไม่ใช่ค่าที่วัดยืนยันแล้ว ส่วนอื่นที่ยังไม่ทำเป็น `null`

ภาพหน้ามีมุมหันเล็กน้อยและขอบโครเมียมซ้าย–ขวาไม่เท่ากัน ภาพหัวหลังสูงต่อกว้างกว่าภาพหน้าราว 3% ขณะที่โมเดลเดียวที่มอง orthographic หน้า–หลังต้องมีขอบนอกเหมือนกัน จึงใช้ค่าเฉลี่ยของเส้นรัศมีหน้า–หลังกับการทำสมมาตรซ้าย–ขวา แล้วแสดงความคลาดเคลื่อนกับเส้นดิบทั้งสองภาพ ไม่แก้ต้นฉบับให้สมมาตรและไม่ยืดภาพแยกแกน

## รูปทรงและโครงสร้างไฟล์

- `HEAD_OUTER_CHROME`: ขึ้นผิวด้วยหน้าตัดแนวนอนจากเส้นที่วัด ไม่ใช้ทรงกลม UV ของ draft
- `HEAD_SHELL_WHITE`, `HEAD_SHELL_WHITE_BACK`: แผ่นขาวด้านหน้าและหลังแยกชิ้น
- `FACE_LOWER_CHROME`, `FACE_CHIN_WHITE`: พื้นที่แถบโครเมียม W และคางตามเส้นภาพ ไม่แทนด้วยท่อรอยยิ้ม
- `EYE_HAPPY_L`, `EYE_HAPPY_R`: ตาแยกชิ้น ใช้รูปร่างและตำแหน่งฉายที่วัดโดยตรง การบังคับคู่ตาให้อยู่กลางขอบหัวทำให้คลาดจากต้นแบบราว 5 พิกเซล จึงคงพิกัดภาพไว้ตามลำดับความสำคัญในสเปก ประเด็นความสมมาตรของหน้าจริงยังไม่ยืนยันเพราะต้นแบบเอียงเล็กน้อย
- มี 4 base materials ตามชื่อในสเปก แต่ภาพตรวจใช้ clay ที่ลดแสงสะท้อน ไม่ใช่งานจูนวัสดุขั้นสุดท้าย
- มี `REF_IMAGES`, กล้อง orthographic หน้า/ข้าง/หลัง และกล้องเฉียงประกอบการตรวจ ภาพอ้างอิง pack ในไฟล์ Blender และไม่เรนเดอร์
- เก็บ Solidify modifiers ไว้แก้ไข ไม่ apply เพื่อเตรียม rig หรือ optimize topology

หน้าและหลังจัดกึ่งกลางและปรับขนาดแบบคงสัดส่วนด้วยความกว้างหัว ภาพเฉียงใช้ความสูงเป็นเกณฑ์เพื่อรักษาการหดของความกว้างจากมุมหัน แต่ทั้งมุมกล้องและความลึกยังไม่ทราบแน่นอน จึงไม่ใช้ภาพเฉียงตัดสินว่าผ่าน ไม่สร้าง `side_overlay.png` ปลอมจากภาพเฉียง

ค่า IoU เปรียบเทียบกับ **เส้นที่คนแกะจากภาพขนาดเล็ก** ไม่ใช่โมเดล CAD ต้นฉบับ ส่วนเปอร์เซ็นไทล์ 95 แสดงระยะขอบในหน่วยพิกเซลของต้นฉบับ เกณฑ์ 3 พิกเซลเป็นตัวช่วยรีวิวของงานนี้ ไม่ใช่เกณฑ์ที่ผู้ใช้อนุมัติ การตรวจชิ้นหน้า/คาง/W/ตาใช้ alpha จากเรนเดอร์แต่ละ mesh จริง แต่ไม่ได้รับรองว่าไม่มีผิวชนกันทุกมุม

## สร้างซ้ำ

ใช้ Python ที่มี Pillow, NumPy, OpenCV และ Blender 4.5.3 LTS จากรากโปรเจกต์:

```powershell
python scripts/prepare-emma-head-reference.py
& 'path/to/blender.exe' --background --python scripts/build-emma-head-match.py
python scripts/compare-emma-head-match.py
```

คำสั่งเขียนทับเฉพาะผลของหัวในโฟลเดอร์นี้ หากแก้ไฟล์ Blender ด้วยมือให้บันทึกอีกชื่อก่อนสร้างซ้ำ

หยุดที่การตรวจหัวตามคำสั่งของผู้ใช้ ยังไม่อนุมัติ geometry และไม่ดำเนินไปยังลำตัว วัสดุขั้นสุดท้าย rig หรือแอนิเมชันอัตโนมัติ
