# ผลอ่านกลุ่มท่าและทดสอบช่อง 1–5 — 11 กันยายน 2026

## ข้อค้นพบที่เปลี่ยนวิธีทดสอบ

ภาพกล้องช่อง 5 แสดงแขนด้านซ้ายของภาพกางออกต่อหลังช่วงที่สคริปต์ตั้งให้ส่ง `#STOP` ทั้งรอบ P1500/T9999 และ P1540/T3000 บันทึก serial แต่ละรอบมี `#STOP+OK` สามชุด จึงไม่ใช้ ACK หรือเวลาส่ง STOP เป็นหลักประกันว่าแขนหยุดแล้ว ค่า P เพิ่ม 40 ยังใช้รับรองระยะมุมเล็กน้อยไม่ได้

ภาพมีเวลาอ้างอิงจากการเริ่มโปรเซสคำสั่ง ไม่ใช่เวลาที่แต่ละไบต์ถึงบอร์ด ไม่มี encoder หรือการวัดมุมข้อต่อ จึงยังไม่ฟันธงว่าเป็นโหมดควบคุมความเร็ว ความหมายของ T ต่างจากที่คาด หรือการเคลื่อนจากคำสั่งก่อนหน้ายังค้างอยู่

หยุดส่งคำสั่งเคลื่อนที่หลังรอบช่อง 5 และ API รายงาน armed=false ณ จบรอบ เจ้าของแจ้งว่ายังไม่ได้ปิดไฟหลัก ข้อมูลนี้ไม่ใช่สถานะสดต่อเนื่องและไม่ใช่การรับรองว่าหุ่นปลอดไฟ ไม่ส่งท่ากลับจุดเริ่มหรือ home เพื่อแก้ท่าที่ค้าง

## กลุ่มท่า 26 กลุ่ม

วิเคราะห์โปรแกรม [RIOS_USC จากผู้ผลิต](https://dl.torobot.com/down/rios_usc.exe) แบบอ่านไฟล์เท่านั้น ไม่รันหรือติดตั้ง พบ `#Read\r\n` และข้อความอ่านจำนวนกลุ่มท่า อ่านจริงครั้งเดียวหลังล็อก API ได้ `#R+OK+026` เป็นจำนวนกลุ่มที่บอร์ดรายงาน ไม่ใช่รายชื่อกลุ่ม ไม่รับรองว่าเลขเรียง 1–26 และไม่ใช่ข้อมูล keyframe หรือค่าตำแหน่งข้อต่อ

SHA256 ของไฟล์โปรแกรม: `5dc2ae28d6c347d5a35ef76a100f82f75ba502287efffc55fc93148aa6aa3a38` ยังไม่มีเส้นทางอ่านท่าภายในครบที่พิสูจน์แล้ว ไม่ทดลองคำสั่ง flash/upgrade/reset ที่พบเพียงสตริง

## การพักทดลองและงานที่เหลือ

สคริปต์ `probe_robot_arm_stop.py` ปฏิเสธทุกโหมดที่ขยับ (map, centre, step, group) ก่อนอ่าน config หรือติดต่อหุ่น โหมดสังเกตกล้องและการอ่านไฟล์ยังทำได้ การพักนี้ไม่ใช่อินเตอร์ล็อกของปุ่มเว็บหรือการตัดไฟจริง หน้า arm/console แสดงข้อจำกัด STOP ที่พบแล้ว

ต้องตรวจรุ่นและโหมดของบอร์ดขับมอเตอร์ ความหมายของ P/T และเส้นทางหยุดทางกายภาพก่อนกลับไปทดสอบรายข้อต่อ ยังไม่ควรไล่ทุกช่อง/เลขกลุ่มโดยสุ่ม บอร์ดมีไฟและยังไม่ระบุจุดตัดไฟเซอร์โวแยกได้ จึงไม่ให้ถอดสายหรือปรับตัวปรับภายในขณะเปิดอยู่

พัก FACE_ENABLED=false ชั่วคราวเพื่อให้กล้องคอมใช้สังเกตหุ่นได้ ค่าเดิม true เก็บไว้ในหลักฐาน ignored การคืนค่านี้ต้องประสานกับการเลิกใช้กล้องทดสอบเพื่อไม่ให้โปรเซสแย่งกล้องกัน
