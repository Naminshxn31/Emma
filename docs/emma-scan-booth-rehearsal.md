# ตู้สแกนหน้า → หุ่นจำได้: ติดตั้งและซ้อม

เจ้าของ 23 พ.ย. 2026: *"ให้คนสแกนแล้วให้ส่งข้อมูลมาที่หุ่นเลยให้หุ่นจำได้"* · *"เราจะเก็บข้อมูลนี้ไว้ เพราะจะให้หุ่นจำได้เวลาวันอื่นที่ลูกค้ามาดูโครงการ"*
· *"เขียนแจ้งไว้"* · *"ทำมาแบบเต็มที่สามารถเอาไปซ้อมได้"*

แขกยืนที่ตู้ (คอม Windows + กล้อง) → อ่านข้อความแจ้ง → กด "ยินยอม" → หันหน้าตามเสียง 5 ท่า → พิมพ์ชื่อ → ข้อมูลใบหน้า
(ตัวเลข ไม่ใช่รูป) วิ่งผ่าน Wi-Fi เข้าหุ่นโดยตรง (HTTPS ปักใบรับรอง + กุญแจของตัวเอง ไม่ผ่าน cloud) → ไม่กี่วินาทีต่อมา
หุ่นเห็นหน้าคนนี้ก็ทักด้วยชื่อ ทั้งในงานและ**วันที่เขากลับมาดูโครงการ** (วันอื่นทักว่า "ยินดีต้อนรับกลับมา") จนถึงวันที่บนข้อความแจ้ง
(ตั้ง 1 ปีหลังงาน) แล้วลบเองทั้งที่ตู้และที่หุ่น

> **สถานะ:** บน PC รันจริงครบทาง (ตัวรับของหุ่นจริง + HTTPS + ใบรับรองจริง บน loopback: บันทึกถึง "หุ่น" 0.14 วิ, ภาพลบ, หน้าซ้ำถูกปฏิเสธ,
> ถอนถึงหุ่น, กุญแจ/ใบรับรองผิดถูกบอกตรง) **ยังไม่เคยรันบนหุ่นจริง** — ซ้อมครั้งแรกคือครั้งแรก

## 0. ต่อจากจุดเช็กอิน (เจ้าของ 23 พ.ย.: "จุดเช็กอินกับตู้สแกนหน้าเป็นคอมเครื่องเดียวกัน")

```
หน้าเช็กอิน (embassy-agent-preview.../kiosk)          ตู้สแกนบนเครื่องเดียวกัน (127.0.0.1:8771)
 เบอร์ → ค้นหา → ยืนยันว่ามาถึง / แสดงบัตร / ลงทะเบียนหน้างาน
   → "ให้ Emma จำหน้าคุณไหม?" (ก่อนหน้าบัตร)
       [ให้ Emma จำหน้า] ───────────────────────────────▶ EN | ไทย (เริ่ม EN) ข้อความแจ้ง → ยินยอม → 5 ท่า
       [ไม่เป็นไร ไปรับบัตร] / 20 วิ → WELCOME (QR บัตร)   ชื่อ = ชื่อที่ลงทะเบียน (แก้เป็นชื่อเล่นได้) → บันทึก → หุ่น
 WELCOME (QR บัตรของแขกคนนั้น) ◀──────────────────────── จบ / ยกเลิก / ไม่ยินยอม / เดินหนี 90 วิ
```
- **ตั้งครั้งเดียวที่เครื่องนี้ (ใช้เบราว์เซอร์+โปรไฟล์เดียวกับที่จะเปิดหน้าเช็กอินวันงาน):**
  1. เปิด `start-scan-booth.cmd` ค้างไว้ (ตั้ง `BOOTH_RETURN_URL` แล้ว = มันไม่เปิดแท็บตู้เอง)
  2. หน้าเช็กอิน → กดค้าง ⚙ 1 วิ → ติ๊ก **"เครื่องนี้มีตู้สแกนหน้าของ Emma"** → เบราว์เซอร์ถามสิทธิ์ **เข้าถึงเครือข่ายภายใน (local network)** → **อนุญาต**
     → ขึ้น "ตู้สแกนหน้าตอบแล้ว" → บันทึก
  3. ลองหนึ่งรอบ: เช็กอิน → "ให้ Emma จำหน้า" → เบราว์เซอร์ถามสิทธิ์กล้องของ `127.0.0.1:8771` → **อนุญาต** · เลือกกล้องที่มุม "ทีมงาน" ถ้ามีหลายตัว (ตู้จำไว้จนปิดโปรแกรม)
- ปุ่มขึ้นเฉพาะตอนตู้ตอบจริง: ปิดโปรแกรมตู้/ไม่ได้อนุญาตสิทธิ์ = ไม่มีปุ่ม เช็กอินเหมือนเดิม (ไม่มีหน้า "เชื่อมต่อไม่ได้" ที่กลับไม่ได้) · สิทธิ์ไม่เคยถูกถามต่อหน้าแขก
- เว็บส่งให้ตู้แค่ **ชื่อ-นามสกุลที่ลงทะเบียน** (ไม่มีเบอร์ อีเมล เลขบัตร) ในตัวฟอร์ม **ไม่อยู่ใน URL** = ไม่ค้างในประวัติเบราว์เซอร์ ·
  ก่อนไปหน้าเช็กอินกลับหน้าแรก (กด Back ไม่เห็นบัตรของแขก) · ข้อมูลใบหน้าไม่ขึ้นเว็บ/Supabase
- ตู้กลับหน้าเช็กอินตาม `BOOTH_RETURN_URL` ใน `.env` ของตู้ (ตั้งแล้ว) — ไม่ใช่ตามลิงก์ (กันลิงก์พาไปเว็บอื่น) · ไม่ได้ตั้ง = ย้อนกลับหน้าที่มา ·
  โปรแกรมตู้ปิดกลางทาง = ยกเลิก/ไม่ยินยอมยังพากลับได้ · ตู้ห้ามถูกฝังในหน้าเว็บอื่น (frame-ancestors 'none')
- หน้าถามเป็น**หน้าแยก ก่อนหน้าบัตร** (เจ้าของ 23 พ.ย. "ไม่อยากเอาไปรวมไม่งั้นมันจะงง" แล้ว "flow ให้สแกนหน้าขึ้นก่อนจะไปสแกน qr") ·
  กลับจากตู้ = หน้า WELCOME ของแขกคนนั้นทันที (หน้าเช็กอินถือข้อมูลบัตรไว้ใน sessionStorage ของแท็บนั้นระหว่างไปตู้ อ่านครั้งเดียวแล้วลบ ไม่เกิน 10 นาที) ·
  ตู้ไม่ตอบ/สวิตช์ปิด = ไปหน้าบัตรเลยเหมือนเดิม
- **ภาษาบนตู้: ปุ่ม EN | ไทย มุมขวาบน เริ่ม EN ทุกแขก** (เจ้าของ "เลือกภาษาได้ th en", "ค่าเริ่มต้น en") — ข้อความแจ้งทีละภาษา, คำสั่งท่า/ข้อความเตือน/เหตุที่บันทึกไม่ได้
  แปลที่ตู้ (`booth.EN`), เสียงภาษาอังกฤษ = เสียงของ Edge/Windows (คลิปเสียงที่มีเป็นไทย) · มุมจอและแผงทีมงานยังเป็นไทย (ของพนักงาน)
- แขกเดินหนีกลางตู้ (90 วิไม่แตะ ไม่มีหน้าในกล้อง) = ตู้กลับหน้าเช็กอิน **โดยไม่โชว์บัตรของเขา** (คนถัดไปจะไม่เห็น) — ให้เขากด "แสดงบัตร" ใหม่ ·
  ตรวจลำดับนี้ซ้ำได้ด้วย `scripts/check_kiosk_booth_flow.py` (ใช้ตู้ทดสอบพอร์ต 18771 ไม่ยุ่งกับตู้จริง)
- **อัปเดตตู้แล้วต้องปิดหน้าต่าง `start-scan-booth.cmd` แล้วเปิดใหม่** — หน้าตู้อ่านไฟล์ใหม่ทุกครั้ง แต่โปรแกรมที่เปิดค้างยังเป็นโค้ดเก่า (ปุ่มภาษาไม่ทำงานกับโปรแกรมเก่า)
- **`start-scan-booth.cmd` ไม่ใช่ `check-scan-booth.cmd`** (ตัวหลังแค่ตรวจ ไม่เปิดตู้) · เปิดซ้อนสองหน้าต่างไม่ได้ (ตัวที่สองบอกว่ามีตู้เปิดอยู่แล้ว)
- **เว็บเช็กอินที่ใช้งานจริงยังไม่มีปุ่มนี้จนกว่าจะอัปโหลด `deploy/` ใหม่** (README ของเว็บ ข้อ deploy) · Edge ของเครื่องจริงยังไม่ได้ลอง (วัดบน Chromium 151)

## 1. เครื่องตู้ (ทำครั้งเดียว)

1. **คอม Windows + กล้อง** ต่อ **Wi-Fi วงเดียวกับหุ่น** (เราเตอร์ Emma-Robot หรือวงที่หุ่นอยู่วันนั้น) · ตั้งให้หันหน้าคนยืนตรง แสงหน้าสว่าง ไม่ย้อนแสง
2. ถ้าเป็น**เครื่องนี้ (PC ที่ deploy หุ่น)** ข้ามไปข้อ 3 ได้เลย · ถ้า**เครื่องใหม่**: ลง **Python 3.14** (รีโปล็อกไว้ที่ 3.14 —
   3.12 ติดตั้ง requirements ไม่ผ่าน) ก๊อปโฟลเดอร์ `condo-voice` ทั้งโฟลเดอร์ (หรือ git clone) แล้ว
   ```
   py -3.14 -m venv .venv
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python scripts\fetch_face_model.py
   ```
   และก๊อป `certs\lan-cert.pem` จาก PC ที่ deploy หุ่นมาวางที่เดียวกัน (**ไฟล์ cert เท่านั้น — ห้ามก๊อป `lan-key.pem`**)
3. สุ่มกุญแจหนึ่งครั้ง: `.venv\Scripts\python scripts\booth_app.py --new-key` → ได้บรรทัด `GUEST_SYNC_KEY=...`
4. ใส่ใน `.env` ของเครื่องตู้:
   ```
   BOOTH_CONSENT_UNTIL=2027-12-02T00:00:00+07:00   # จอบอกแขก "ถึงวันที่ 1 ธันวาคม 2570" (ไกลสุด 400 วัน)
   BOOTH_CONTROLLER=<ชื่อนิติบุคคลผู้ควบคุมข้อมูล>    # ขึ้นบนข้อความแจ้ง — ว่าง = ตู้ไม่เปิดสแกน
   BOOTH_CONTACT=<ช่องทางติดต่อ เช่น เบอร์สำนักงานขาย / LINE>   # ขึ้นบนข้อความแจ้ง — ว่าง = ตู้ไม่เปิดสแกน
   BOOTH_PIN=<เลข 4–6 หลัก>                        # ทีมงานใช้ถอนความยินยอมที่ตู้ — ว่าง = ถอนที่ตู้ไม่ได้เลย
   GUEST_SYNC_URL=https://<ip หุ่น>:8004
   GUEST_SYNC_KEY=<จากข้อ 3>
   ```
   `BOOTH_CONTROLLER` / `BOOTH_CONTACT` เป็นข้อมูลของบริษัทที่ผมไม่ได้แต่งให้ — ตอนซ้อมใส่อะไรก็ได้ แต่ก่อนวันงานต้องเป็นของจริง
   (มันคือข้อความที่แขกกดยินยอม)

**IP หุ่น:** ดูจากหน้าคุมแอป หรือ `adb mdns services` · IP เปลี่ยนตาม DHCP → ถ้าตั้งได้ ให้จองที่อยู่หุ่นในเราเตอร์ (192.168.0.1)
ไม่งั้นวันไหนหุ่นได้ IP ใหม่ ตู้จะขึ้น "ติดต่อหุ่นไม่ได้" ต้องแก้ `GUEST_SYNC_URL`

## 2. ฝั่งหุ่น (ทำครั้งเดียว บน PC ที่ deploy หุ่น)

1. ใส่ `GUEST_SYNC_KEY=<ตัวเดียวกับข้อ 1.3>` ใน `.env` ของ PC นี้ (robot.env เปิด `FACE_GUESTS_FILE` + `GUEST_SYNC_PORT=8004` ไว้แล้ว — กุญแจห้ามอยู่ใน robot.env)
2. ```
   python scripts/robot_server.py deploy     # โค้ดใหม่ (เก็บได้ 400 วัน) + robot.env
   python scripts/robot_server.py secrets    # .env ที่มีกุญแจ
   python scripts/robot_server.py restart
   ```
   ค่าของตู้ (`BOOTH_*`, `GUEST_SYNC_URL`) ไม่ถูกส่งขึ้นหุ่น (ENV_DROP) — ตู้เป็นเครื่องนี้ก็ได้
3. ถ้าหุ่นยังไม่ deploy โค้ดใหม่ ตู้จะขึ้น "หุ่นยังใช้โค้ดเก่า (เก็บได้ 30 วัน)" — หุ่นรุ่นเก่าจะปฏิเสธทุกคนที่สแกน

## 3. ตรวจก่อนซ้อม — `check-scan-booth.cmd`

ดับเบิลคลิก (หรือ `python scripts/booth_app.py --check`) ไม่เปิดกล้อง ทุกแถวต้องเป็น `[ ok ]` แล้วบรรทัดสุดท้ายขึ้น **"พร้อมซ้อม"**

| ขึ้นว่า | แก้ |
|---|---|
| ไม่มีโมเดลใบหน้า | `python scripts/fetch_face_model.py` |
| ข้อความแจ้งยังมีช่องว่าง | ใส่ `BOOTH_CONTROLLER` / `BOOTH_CONTACT` |
| ติดต่อหุ่นไม่ได้ | ตู้กับหุ่นคนละ Wi-Fi / IP หุ่นเปลี่ยน / แอป Emma บนหุ่นปิด (เซิร์ฟเวอร์ไม่ทำงาน) / ยังไม่ `restart` หลังข้อ 2 |
| รอส่งถึงหุ่น N (ส่งไม่ได้เพราะ: ...) | `bad_consent` = หุ่นโค้ดเก่า → deploy · `wrong_model` = โมเดลคนละรุ่น · `off` = หุ่นไม่ได้ตั้ง FACE_GUESTS_FILE · ชื่อ error ของเน็ต = ติดต่อไม่ได้ — **ข้อมูลไม่หาย** ส่งเองเมื่อแก้แล้ว |
| ใบรับรองของหุ่นไม่ตรง | ก๊อป `certs/lan-cert.pem` ชุดเดียวกับที่ส่งขึ้นหุ่นมาใหม่ |
| หุ่นปฏิเสธกุญแจ | `GUEST_SYNC_KEY` สองฝั่งไม่ตรง → แก้แล้ว `secrets` + `restart` (ผิด 5 ครั้งหุ่นล็อกตู้ 1 นาที) |
| โมเดลคนละรุ่น | เครื่องตู้โหลดโมเดลคนละตัว → `fetch_face_model.py` ใหม่ |
| หุ่นยังใช้โค้ดเก่า | `robot_server.py deploy` + `restart` |

ตอนตู้เปิดอยู่ มุมขวาล่างของจอบอกสถานะหุ่นทุก 30 วิ: **"หุ่นพร้อม"** หรือข้อความสีแดง + จำนวนที่ "รอส่งถึงหุ่น"
· **"หุ่นปฏิเสธ N — ดูหน้าต่างคำสั่ง"** = แขกที่จอบอกแล้วว่า "อีกสักครู่เธอจะรู้จักคุณ" แต่หุ่นไม่รับทีหลัง (หน้าซ้ำ/ชื่อซ้ำ) —
ชื่ออยู่ในหน้าต่างคำสั่งของตู้ ตามตัวเขามาสแกนใหม่ (ตู้ลบสแกนนั้นแล้ว)

## 4. ซ้อม (เปิดตู้ด้วย `start-scan-booth.cmd` แล้วกด F11)

ใช้คนทดสอบที่รู้ตัวว่ากำลังลงทะเบียน · หุ่นเปิดแอป Emma (หรือ Emma Event) มีสาย/กล้องทำงานตามปกติ

| # | ทำ | ผ่านเมื่อ |
|---|---|---|
| A | คนที่ 1 สแกนครบ พิมพ์ชื่อ บันทึก | จอขึ้น "เรียบร้อยแล้วค่ะ · Emma รู้จักคุณแล้ว" (ถ้าขึ้น "กำลังส่ง" = ยังไม่ถึงหุ่น ดูมุมจอ) · `check-scan-booth.cmd` บอกแขกบนหุ่น 1 คน |
| B | คนที่ 1 เดินไปยืนหน้าหุ่น หน้าตรง ระยะ 1–3 ม. คนเดียวในภาพ | หุ่นทักด้วยชื่อภายในไม่กี่วินาที (ไม่ถึง: ดูข้อ 6) |
| C | คนที่ไม่ได้สแกนยืนหน้าหุ่น | ทักแบบไม่มีชื่อ ห้ามถูกเรียกชื่อใคร |
| D | คนที่ 1 สแกนอีกรอบด้วยชื่ออื่น | ตู้ปฏิเสธ "ใบหน้านี้มีอยู่ในระบบแล้วภายใต้ชื่ออื่น" และไม่เก็บ |
| D2 | คนที่ 3 สแกนโดยพิมพ์ชื่อพนักงานที่หุ่นรู้จักอยู่แล้ว | หุ่นปฏิเสธ "ชื่อนี้ซ้ำกับคนที่ Emma รู้จักอยู่แล้ว" (ชื่อพนักงานไม่ถูกแตะ) |
| E | ปิด Wi-Fi ของตู้ → คนที่ 2 สแกน → เปิด Wi-Fi | จอบอก "กำลังส่ง" มุมจอ "รอส่งถึงหุ่น 1" → เปิดแล้วไม่เกิน ~30 วิ ตัวเลขหาย และหุ่นทักคนที่ 2 ด้วยชื่อ |
| F | ทีมงาน (มุมจอ) → ชื่อคนที่ 1 + PIN → ถอนและลบข้อมูล | "ถอนแล้ว ลบข้อมูลแล้ว" · คนที่ 1 ยืนหน้าหุ่นอีกครั้ง = ทักแบบไม่มีชื่อ · PIN ว่าง/ผิด = ไม่ถอน |
| G | พรุ่งนี้ (วันที่ไทยเปลี่ยน) คนที่ 2 ยืนหน้าหุ่น | หุ่นทัก "ยินดีต้อนรับกลับมา / Welcome back" แทนการถามว่ารู้จักโครงการไหม |
| H | สองคนยืนหน้าหุ่นพร้อมกัน (คนหนึ่งสแกนแล้ว) | ไม่เรียกชื่อ (ชื่อเดียวกับสองคน = ทักผิดคน) |

**การเดินเข้าหาแขก (Emma Event)** เป็นขั้นแยก มีคนถือ E-stop — แผนอยู่ใน [emma-face-approach.md ข้อ 7](emma-face-approach.md) robot.env ตอนนี้เป็น dry run
(คำนวณแล้วจด `would_walk` ไม่หมุนล้อ)

## 5. หลังซ้อม ก่อนวันงาน

1. **ลบแขกทดสอบทุกคน:** `python scripts/booth_app.py --list` (รายชื่อขึ้นในหน้าต่างคำสั่ง ไม่ขึ้นจอ) แล้วถอนทีละชื่อที่มุมจอ "ทีมงาน"
   (ชื่อที่ถอนแล้วใช้ซ้ำที่ตู้ไม่ได้ 7 วัน — ตั้งชื่อคนทดสอบให้ไม่ชนแขกจริง เช่น "ทดสอบ1")
2. `BOOTH_CONTROLLER` / `BOOTH_CONTACT` เป็นของจริง แล้วเปิดตู้ อ่านข้อความแจ้งบนจอจริงหนึ่งรอบ
3. `check-scan-booth.cmd` = "พร้อมซ้อม" ที่สถานที่จริง (Wi-Fi ของวันงาน)
4. มีเจ้าหน้าที่ยืนข้างตู้ (ตู้ตรวจอายุไม่ได้ ช่วยคนที่ไม่ถนัดภาษา — คำสั่งท่าทางเป็นเสียงไทย)
5. **ให้เจ้าของตัดสิน: `WALK_FRAMES`** (robot.env เปิด) เก็บภาพกล้องหัวของทุกคนที่หุ่นเห็นระหว่างเดิน 7 วันบนหุ่น — ไม่ใช่ข้อมูลของตู้
   และไม่อยู่ในข้อความแจ้ง เสนอปิดวันงาน (`docs/emma-face-approach.md` ข้อ 6.4)

## 6. หุ่นเห็นแต่ไม่เรียกชื่อ — เหตุที่เป็นไปได้ (ทุกข้อ = ทักแบบไม่มีชื่อ ไม่ใช่ทักผิดคน)

- **คะแนนต่ำกว่า 0.60** (เกณฑ์ของแขก สูงกว่าพนักงาน เพราะแขกหลักร้อยคน): หันข้าง เบลอ ไกลเกิน ~4 ม. แสงต่างจากตู้มาก
- **มีคนอื่นในภาพ** (กฎชื่อเฉพาะตอนอยู่คนเดียว)
- **ยังไม่ถึงหุ่น** (มุมจอตู้ยังมี "รอส่งถึงหุ่น")
- **กล้องหัวแคบ 19°**: หุ่นเห็นเฉพาะคนที่อยู่ตรงแนวหน้าหัว — วางหุ่นหันเข้าทางคนเดินเข้า
- ดูเหตุผลจริงใน log หุ่น: แถว `face_seen` มี `unnamed=<เหตุผล>` (`python scripts/analyze_log.py`) — ชื่อแขกไม่ลง log

## 7. วันขายหลังงาน

- หุ่นจำแขกได้เองตลอด ไม่ต้องเปิดตู้ · ลบเองเมื่อถึงวันที่บนข้อความแจ้ง (เช็คทุกชั่วโมงทั้งตู้และหุ่น)
- **แขกขอถอน/ลบในวันขาย:** เปิดตู้ (เครื่องตู้เครื่องไหนก็ได้ที่ตั้งค่าครบ อยู่ Wi-Fi เดียวกับหุ่น) → ทีมงาน → ชื่อ + PIN ·
  หาชื่อที่เขาพิมพ์ด้วย `booth_app.py --list` · หุ่นหยุดเรียกชื่อเฟรมถัดไปและลบแถวใบหน้าทันที
  · **ห้ามรัน `scripts/revoke_face.py` บนหุ่นผ่าน su** — มันเขียน `people.json` ใหม่เป็นไฟล์ของ root ที่เซิร์ฟเวอร์ (nobody) อ่านไม่ได้
  แล้วหุ่นไม่เรียกชื่อใครเลย (พนักงานด้วย) และไม่รับแขกจากตู้ จนกว่าจะแก้สิทธิ์ไฟล์ — ใช้ทางตู้เท่านั้น
- ตู้ใช้รับแขกใหม่ในวันขายได้ แต่ทุกคนหมดอายุวันเดียวกัน (`BOOTH_CONSENT_UNTIL`) — ถ้าจะใช้ยาวต้องตั้งวันใหม่ และข้อความแจ้งจะบอกวันใหม่เอง
- **ตู้ลบข้อมูลตามวันได้เฉพาะตอนโปรแกรมตู้เปิดอยู่** (หุ่นลบเองตลอดเพราะเปิดทุกวัน) — ถ้าหลังงานจะไม่เปิดตู้อีก:
  `python scripts/booth_app.py --wipe` ล้างข้อมูลแขกทั้งหมดบนเครื่องตู้ (ไม่ยอมล้างถ้ายังมีรายการรอส่งถึงหุ่น) หุ่นยังจำได้ตามวันของมัน
  และถอนในวันขายยังทำจากตู้ได้ (ตู้ส่งคำถอนถึงหุ่นแม้ไม่มีข้อมูลคนนั้นแล้ว)
