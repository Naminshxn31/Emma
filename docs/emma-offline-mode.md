# Emma ตอนอินเทอร์เน็ตใช้ไม่ได้ (โหมดออฟไลน์ฉุกเฉิน)

คำถามของเจ้าของ (26 ต.ค. 2026): *"เพิ่มด้วยกรณีที่เน็ตไม่ดี จะต้องทำยังไง ใช้ local model แทนดีไหม ลองไปเช็คจากข้อมูลที่เคยถาม ทำสำรองเผื่อกรณีฉุกเฉิน"*

คำตอบสั้น: **ไม่ใช้ LLM ในเครื่อง** — ใช้ "ตัวสำรองที่ไม่แต่งคำ" แทน: หุ่นฟังเองในเครื่อง (ASR สองตัว), เลือกคำตอบด้วยกฎ, พูดได้เฉพาะ **ประโยคที่คนอนุมัติแล้ว** กับ **บรรทัดของเรื่องเล่าที่อนุมัติแล้ว** ด้วยเสียง Emma ที่อัดไว้ล่วงหน้าตอนเน็ตยังดี และ **ทางแก้ที่คุ้มที่สุดคือเราเตอร์ 4G สำรอง** (ท้ายเอกสาร)

ทั้งหมดอยู่หลังสวิตช์ `OFFLINE_FALLBACK` (ปิดเป็นค่าเริ่มต้น) — ปิดอยู่ = เครื่องห้องขายและหุ่นทำงานเหมือนเดิมทุกไบต์

**ตอนเน็ตล่มจริง ลูกค้าเจออะไร (ก่อนงานนี้):** ไม่มีเสียงเลยแม้แต่ประโยคเดียว — จอขึ้น "Connecting…" สูงสุด 10 วิ (อาจถึง ~40 วิ) แล้วกลับเป็น "Ready" ทั้งที่พูดไม่ได้ และวนต่อใหม่ทุก ~15 วิทั้งวัน

## 2. ทำไมไม่ใช้ LLM ในเครื่อง

- **ช้า:** บริบทที่อนุมัติ (facts + sales context) ~1,660 token บน RK3588 ต้อง prefill 5–65 วิ ต่อคำตอบ (แล้วแต่รุ่น/ตัวรัน) + สังเคราะห์เสียงไทยอีก ~3 วิ → **เงียบ 10–40 วิต่อคำตอบ** เทียบ Gemini 1.1 วิ
- **ไทยอ่อน:** รุ่นที่รันบนหุ่นได้ (1–4B) คะแนนภาษาไทยต่ำ (เช่น Typhoon2-1B Thai MT-Bench 3.97/10) และ model card เขียนเองว่าอาจตอบผิด
- **ผิดกฎหลักของโปรเจกต์:** โมเดลเล็กจะถอดความตัวเลขผิด (ราคา ขนาด จำนวนห้อง) ในทางฉุกเฉินที่ไม่มีใครตรวจ — ตรงกับสิ่งที่เจ้าของห้ามที่สุด "ห้ามแต่งข้อมูลโครงการ"
- งานเดียวที่ LLM ทำได้อย่างปลอดภัยคือ "เลือก id คำตอบ" ซึ่งกฎ + ตัวจับคู่ที่มีอยู่ทำได้แล้วในเสี้ยววินาที

**สัญญาอนุญาตของตัวถอดเสียง (ยังไม่ได้ยืนยันสำหรับใช้ในห้องขาย):** whisper-base = MIT (น้ำหนักของ OpenAI) · zipformer-thai = น้ำหนัก Apache-2.0 แต่เทรนด้วย GigaSpeech 2 ซึ่งเงื่อนไขการเข้าถึงข้อมูลเขียนว่า "เพื่อการวิจัยและการศึกษาที่ไม่ใช่เชิงพาณิชย์เท่านั้น" และหน้าชุดข้อมูลบอกว่าโมเดลที่เทรนจากข้อมูลนี้ "อาจ" ใช้เชิงพาณิชย์ได้ โดยให้ผู้ใช้ตรวจสอบเอง — **เจ้าของ/บริษัทต้องตัดสินก่อนเปิด `OFFLINE_FALLBACK` บนหุ่น** (ตัวสำรองที่วัดไว้คือ streaming zipformer 8 ภาษา CER ไทย 16.3% ซึ่งต้องตรวจสัญญาอนุญาตแบบเดียวกัน)

**ไม่มี TTS ในเครื่องในรอบนี้:** เสียงผู้หญิงไทยตัวเดียวที่รันได้ (MMS-TTS-THAI-FEMALEV2) ดัดแปลงจาก Meta MMS ซึ่งเป็นสัญญาอนุญาต **CC-BY-NC (ห้ามใช้เชิงพาณิชย์)** และเป็นเสียงผู้หญิงอีกคนที่ไม่ใช่ Emma — ใช้เสียง Emma ที่อัดล่วงหน้า (Gemini TTS เสียง `GEMINI_VOICE` เดียวกับสายสด) แทน

## 3. ตอนออฟไลน์ Emma ทำอะไรได้ / ไม่ได้

**ได้:**
- **เล่าเรื่องด้วยภาพ (stories) ที่อนุมัติแล้ว** — คำถามที่ตรงเรื่อง ภาพขึ้นจอเหมือนออนไลน์ พูดบรรทัด `say` ตามภาษาที่คุยอยู่ (ไทย/อังกฤษ) แตะภาพ/ปุ่มบนเรื่องเล่าไปเรื่องต่อได้
- **ประโยคตายตัว 8 ประโยค (หลังอนุมัติเท่านั้น):** คำทักตอนกล้องเห็นคน, ขอให้พูดซ้ำ, เมนูว่าตอนนี้เล่าอะไรได้, ส่งต่อทีมขาย (เรื่องที่ต้องใช้ข้อมูลล่าสุด: ราคา ห้องว่าง เวลาเปิด การจอง), ส่งต่อทีมขายเรื่องอื่น, เรื่องนอกโครงการ, คำถามชวนเลือกส่วนของโครงการ (`invite` — ตอบคนที่ทักกลับหลังคำทักของกล้อง หรือขอภาษาซ้ำ), ตอบรับคำขอบคุณ/ลา
  - **ประโยคส่งต่อทีมขายไม่เอ่ยคำว่า "ราคา" และไม่สัญญาว่าจะเล่าอะไร** (รีวิว 26 ต.ค.): ด่านเชิงพาณิชย์จับ "ฟิตเนสเปิดกี่โมง" "สร้างเสร็จเมื่อไหร่" "จองห้องประชุม" ด้วย — ประโยค "เรื่องราคาและห้องที่ยังว่าง…" ไปตอบคำถามเวลาเปิดฟิตเนส = Emma เปิดเรื่องราคาเอง ซึ่งเจ้าของห้าม (8 ต.ค.) และ "ดิฉันเล่าเรื่องสิ่งอำนวยความสะดวกได้" หลังคำถามเรื่องสิ่งอำนวยความสะดวกที่เพิ่งตอบไม่ได้ = สัญญาที่ทำไม่ได้ (มีเทสต์ทั้งสองข้อ)
- **หยุดด้วยเสียง:** "หยุด" / "stop" / "พอแล้ว" → ตัดเสียงของเธอทันที และเรียกเครื่องมือหยุด (`stop_moving` หรือ `move_body(stop)`) ที่สายนั้นมองเห็น ไม่พูดอะไรตอบ — ระหว่างหุ่นเดิน/ทำท่า ประโยคไหนมีคำหยุดก็หยุด, ยืนนิ่ง = คำหยุดล้วนๆ เท่านั้น ("wait, what about the pool?" ยังเป็นคำถามเรื่องสระ) · **ทางหยุดที่เชื่อได้ยังเป็นปุ่ม E-stop บนตัวหุ่น** (หยุดด้วยเสียงต้องได้ยินก่อน และถ้าตัวถอดเสียงยังไม่โหลดก็ไม่ได้ยิน)
- **เงียบใส่เสียงคนคุยกันเอง** — ด่าน "พูดกับเธอจริงไหม": ต้องมีคำที่มีความหมาย + รูปคำถาม/คำขอ + ไม่มีคำสแลงของคนคุยกัน (เฮ้ย, วะ, พี่, อันนี้…ใช่ไหม ฯลฯ) + มีคำของโครงการ + ไม่ยาวเกิน 80 ตัวอักษร

**ไม่ได้ (โดยตั้งใจ):**
- ราคา ห้องว่าง ผังห้องจริง → ส่งต่อทีมขาย (ต้องใช้ระบบผังขายซึ่งต้องมีเน็ต และประโยคตายตัวห้ามมีตัวเลข)
- คำตอบจาก FAQ ของรายงาน / ข้อความสไลด์ → **ไม่พูด** วัดแล้ว: FAQ พูดได้ตรงตัวแค่ 10 จาก 55 คำถามที่จับได้ (31 ได้คำตอบผิดภาษา ที่เหลือมีหมายเหตุถึงบอท/แหล่งอ้าง/ตัวเลขขนาด), ข้อความรายงาน/สไลด์ผิด 53%/44% และเด้งกับเสียงรอบข้าง 48%/25% — ไม่มีโมเดลกรองแล้วจะพูดผิดอย่างมั่นใจ
- คุยเล่นอิสระ / แปลภาษา / ความรู้ทั่วไป → ประโยคนอกเรื่อง
- **สายที่ไม่มีเรื่องเล่า (`present_story` มองไม่เห็น เช่นเปิดสวิตช์บน PC หน้าโต๊ะ) = ส่งต่อทีมขายอย่างเดียว:** ไม่มีเมนู (เมนูเอ่ยหัวข้อของเรื่องเล่า) ทุกคำถามโครงการได้ประโยคส่งต่อ · คำทักออฟไลน์ยังถาม "สิ่งอำนวยความสะดวกหรือทำเล" ซึ่งบนเครื่องแบบนั้นตามต่อไม่ได้ — ตัวสำรองนี้ออกแบบมาสำหรับหน้าหุ่นที่มีแคตตาล็อกเรื่องเล่าที่อนุมัติแล้ว
- ภาษาที่สามขึ้นไป → ตอบเป็นอังกฤษ (เรื่องเล่ามีแค่ไทย/อังกฤษ)
- คำสั่งที่ส่งถึง "โมเดล" (ถามต่อหลังเงียบ, กล่าวลา, หุ่นเดินถึง) → ข้าม (ประโยคตายตัวตอบคำสั่งที่อ่านไม่ออกไม่ได้)

**ผลวัดบนตารางคำถามจริง (ตัวเลขเท่านั้น):**

| | ผล |
|---|---|
| เสียงรอบข้าง/เศษคำ (636) | พูดตอบ 17 ครั้ง (2.7%) — ก่อนมีด่าน 222 |
| เรื่องเล่าเด้งใส่เสียงรอบข้าง/คำทัก | 12 → 5 (ด่านคำ) → 0 (คำเดียวไม่นับ ยกเว้นตอบคำถามของเธอ) |
| คำถามโครงการ (202 ไม่รวมการแตะ) | เรื่องเล่า 69 (ตรง 67 ที่เหลือบางส่วน ผิด 0), เมนู 112, เงียบ 20, ส่งทีมขาย 1 |
| คำถามราคา (19) | ส่งทีมขาย 18 |
| ทักทาย (71) | คำทัก 7, ตอบรับ 3, เงียบ 61 (วัดก่อนเพิ่ม `invite` — ตอนนี้คนที่ทักกลับหลังคำทักได้คำถามชวนเลือกแทนประโยคตอบรับ) |

ข้อสังเกต: คำถามโครงการกว่าครึ่งได้ "เมนู" ไม่ใช่คำตอบ เพราะตัวจับเรื่อง (`story_for_query`) ยังจับสำนวนจริงของลูกค้าไม่ครบ — **78 จาก 99 คำถามที่ไม่ได้คำตอบเต็ม เป็นหัวข้อที่มีเรื่องเล่าอยู่แล้ว** การเติมคำถามจริงลงในเรื่องเล่า (ต้องอนุมัติแคตตาล็อกใหม่) จะยกทั้งออฟไลน์และออนไลน์

**ทดสอบปลายทางบน PC ด้วยเสียงสังเคราะห์ (TTS ไม่ใช่เสียงลูกค้า) 30 คำถาม × 4 เสียง/สภาพ:**

| | ไทย (80) | อังกฤษ (40) |
|---|---|---|
| เส้นทางเหมือนเมื่อถอดเสียงสมบูรณ์ | 50 | 39 |
| กลายเป็นเงียบ (ปลอดภัย) | 23 | 1 |
| พูดอย่างอื่น (เมนู↔ส่งทีมขาย, เรื่อง→เมนู) | 7 | 0 |
| ไปผิดเรื่องเล่า | 0 | 0 |

## 4. ทำงานยังไง

```
ไมค์ → VadGate เดิม (พื้นความดัง/focus เดิม) → ช่วงเสียงที่ปิดแล้ว
     → ASR ในเครื่อง (ไทย: zipformer-thai int8 / อังกฤษ+แยกภาษา: whisper-base int8)
     → router (กฎ ไม่มีโมเดล) → เรื่องเล่าที่อนุมัติ / ประโยคที่อนุมัติ / เงียบ
     → คลิปเสียงที่อัดไว้ (24 kHz, ตรวจ sha256 ทุกครั้ง) → หน้าหุ่น
```

- **ตรวจเน็ตโดยไม่เรียก API** (`app/net_health.py`): หาชื่อ `generativelanguage.googleapis.com` แบบเดียวกับที่สายสดใช้ (บนหุ่นผ่าน `robot_dns`) + TCP + TLS :443 ภายใน `NET_PROBE_TIMEOUT_S` (3 วิ) ทุก `NET_PROBE_S` (15 วิ) — **ไม่สลับเพราะสะดุดครั้งเดียว:** ออฟไลน์เมื่อพลาด 2 ครั้งติด (การตรวจ หรือการต่อ Gemini ที่ล้มเพราะเครือข่าย) กลับออนไลน์เมื่อตรวจผ่าน 2 ครั้งติด · turnlog `net_state` เฉพาะตอนเปลี่ยนสถานะ (สถานะ + หมวดเหตุผล ไม่มีข้อความ error)
- **เน็ตครึ่งๆ กลางๆ: ตรวจผ่านแต่ต่อ Gemini ไม่ได้** (รีวิว 26 ต.ค. จำลองแล้ว: proxy/Wi-Fi ที่ตัด websocket, เน็ตช้าจนจับมือไม่ทัน) — เดิมการตรวจที่ผ่านล้างตัวนับทุกครั้ง หุ่นวนทั้งวัน: ต่อ 10–15 วิไม่มีเสียง → สายสำรอง → ~10 วิต่อมาวางเพราะ "เน็ตกลับแล้ว" → ต่อใหม่พลาดซ้ำ · ตอนนี้การต่อ Gemini ที่พลาดเพราะเครือข่ายนับแยก ล้างได้ด้วยการต่อที่สำเร็จเท่านั้น: พลาด 2 ครั้งติด = สายถัดไปเปิดตัวสำรองทันทีโดยไม่ต่อ Gemini 60 วิ (พลาดอีกเท่าตัว สูงสุด 10 นาที — แย่สุดเสียต่อไม่ติดหนึ่งครั้งต่อ 10 นาที) และสายสำรองไม่ถูกวางเพราะการตรวจผ่านระหว่างนั้น · turnlog `dial_backoff` (ครั้งที่พลาดติดกัน + วินาทีที่รอ)
- **ภาษา:** ถ้ารู้ภาษาของบทสนทนาแล้ว (`talk_lang`) ใช้ตัวถอดเสียงภาษานั้นตรงๆ ไม่งั้น whisper แยก "อังกฤษ/ไม่ใช่อังกฤษ" · ข้อแลก: ถ้าคุยไทยอยู่แล้วคนพูดอังกฤษเข้ามา ตัวถอดไทยจะได้คำไทยมั่วๆ → ส่วนใหญ่เงียบ จนสายจบตามเวลา (ดูข้อค้าง)
- **ภาษาที่ตอบ:** ภาษาของบทสนทนา; ภาษาอื่น → อังกฤษ; ยังไม่มีใครพูด (คำทักแรก) → อังกฤษ ตามที่เจ้าของยืนยัน 8 ต.ค.
- **การแตะบนจอ:** ปุ่มเรื่องต่อ → เรื่องนั้น, ปุ่มเลือกแบบห้อง → เรื่องของแบบห้องนั้น (ถ้ามี), ปุ่มที่ต้องใช้ผังขาย → ส่งทีมขาย, แตะภาพเพื่อขยาย → ภาพขยายคือคำตอบ (ส่งทีมขายครั้งแรกครั้งเดียว)
- **สลับตอนต่อสายเท่านั้น ไม่สลับกลางสาย:** การต่อ Gemini ที่ล้มเพราะเครือข่าย → เปิดตัวสำรองบน socket เดิมของหน้าหุ่นทันที (ไม่ส่ง error ไม่ปิดสาย) · สายที่คุยอยู่แล้วเน็ตหลุดกลางสาย = สายนั้นจบ ("Disconnected") แล้วสายถัดไปค่อยเปิดเป็นออฟไลน์ · **สายออฟไลน์สายแรกต้องเสียการต่อที่ล้มหนึ่งครั้งก่อน** (จอขึ้น "Connecting…" ได้ถึง ~10 วิ หรือเท่า `CONNECT_TIMEOUT_S` ถ้าตั้งไว้) จากนั้นสถานะเน็ต/การนับการต่อที่พลาดจะพาสายต่อๆ ไปไปตัวสำรองโดยไม่รอ · พอเน็ตกลับ สายออฟไลน์จบเองตอนเงียบ ~10 วิ (ไม่มีคนพูด ไม่มีเสียงค้าง) ให้สายถัดไปเป็น Gemini — ยกเว้นช่วงรอหลังต่อพลาดติดกัน (ข้างบน) · หน้าหุ่นขึ้นป้าย "Offline mode" ต่อท้ายสถานะ

## 5. ขั้นตอนเปิดใช้ (เจ้าของ/ทีมขายทำ)

1. **อ่านและอนุมัติประโยคตายตัว** (ทุกบรรทัดตอนนี้เป็นร่าง — ร่างไม่ถูกพูดและไม่ขึ้นจอ):
   ```
   python scripts/approve_offline_lines.py --status
   python scripts/approve_offline_lines.py --by "ชื่อ"
   ```
   ไฟล์: `data/projects/embassy_world/offline/lines.json` · แก้ข้อความหลังอนุมัติ = กลับเป็นร่างเอง (ลายเซ็นผูกกับคำ `approved_sha256`) · สคริปต์ปฏิเสธบรรทัดที่มีตัวเลข / "ไม่มีข้อมูล" / "อยู่เองหรือลงทุน" / "แนวคิดเบื้องต้น" / สัญญาว่าจะเรียกพนักงาน / ไทยไม่มีค่ะคะ
2. **อัดเสียง Emma** (ต้องใช้ key แบบจ่ายเงิน — free tier อัดได้ ~10 ประโยค/วัน, key ใช้ร่วมกับห้องขาย ทำนอกเวลาทำการ):
   ```
   python scripts/render_offline_voice.py --dry-run      # นับ + ประมาณราคา ไม่เรียก API
   python scripts/render_offline_voice.py
   ```
   วัด dry-run 26 ต.ค.: บรรทัดเรื่องเล่า 595 คลิป (ไทย 16,222 / อังกฤษ 18,968 ตัวอักษร) ~43 นาทีเสียง **ประมาณ $0.58** (+ ประโยคตายตัว 16 คลิปหลังอนุมัติ) · ใช้โมเดลเดียวทั้งหมด (`OFFLINE_VOICE_MODEL`, ค่าเริ่ม gemini-3.8-flash-tts) เสียง `GEMINI_VOICE` · ผสมสองเสียงในโฟลเดอร์เดียวไม่ได้ (สคริปต์ปฏิเสธ ต้อง `--fresh`) · คลิปอยู่ `data/offline/voice/` (gitignore, ~125 MB)
3. **โหลดตัวถอดเสียงบน PC** (ถ้าจะใช้บน PC ด้วย): `python scripts/fetch_offline_models.py` (~0.9 GB archive → เก็บ ~310 MB ใน `data/offline/asr/`)
4. **เปิดสวิตช์บนหุ่น:** เพิ่ม `OFFLINE_FALLBACK=true` ใน `data/robot-server/robot.env` — **ไฟล์นี้ไฟล์เดียวเปิด/ปิดให้หุ่น** (`ROBOT_ENV_ONLY` ใน robot_server.py: ค่าใน `.env` ของ PC ไม่ถูกส่งไปหุ่น — เดิมเปิดลองบน PC แล้วสั่ง `secrets`/`deploy` = หุ่นเปิดตามโดยเทสต์ล็อกไม่เห็น) · มีเทสต์ล็อก: robot.env เปิดได้เมื่อประโยคตายตัวอนุมัติครบทุกบรรทัดเท่านั้น และ `deploy` พิมพ์คำเตือนถ้าเปิดอยู่ข้างประโยคที่ยังเป็นร่าง · แล้ว `python scripts/robot_server.py secrets` + `deploy` + `restart` (ตัวถอดเสียงที่โหลดไม่สำเร็จจะไม่ลองใหม่จนกว่าเซิร์ฟเวอร์เริ่มใหม่)
   - deploy ส่งคลิป + index ผ่าน adb (~125 MB ≈ 7 นาทีบน adb Wi-Fi) **เฉพาะเมื่อสวิตช์เปิด**
   - หุ่นโหลด archive ตัวถอดเสียงเอง (ปัก sha256, ตรวจก่อนแตก, เอาเฉพาะไฟล์ที่ปัก, ปฏิเสธ path ที่หลุดออกนอกโฟลเดอร์) แล้ว root คัดลอกลง `code/data/offline/asr/` ตรวจ hash ทุกไฟล์
   - ค่าที่เสนอสำหรับหุ่น (ยังไม่ได้ใส่ robot.env): `OFFLINE_ASR_THREADS=1` (คอร์ใหญ่ใช้ร่วมกับ greeter และหน้า 3D)
5. **วัดบนหุ่นก่อนเชื่อตัวเลข:** RAM (วัดบน PC: โหลด 2.6 วิรวมตรวจ sha256, ~0.6 GB หลังโหลด, ~0.86 GB หลังถอดเสียงทั้งสองภาษา — whisper ถูกโหลดสองชุด สำหรับถอดเสียงกับแยกภาษา; เซิร์ฟเวอร์บนหุ่นใช้อยู่ ~1 GB จาก 15.5 GB), RTF จริงข้าง server/greeter, ความแม่นด้วยไมค์ Bothlent ระยะจริง (ตัวเลขข้างบนมาจากเสียงสังเคราะห์และ FLEURS) · โหลดเกิดครั้งเดียวต่อโปรเซส ในเธรด ตอนสายออฟไลน์สายแรกเปิด (ไม่ได้โหลดตอนบูต — จงใจ: 0.6–0.9 GB บนเครื่องที่ส่วนใหญ่ไม่เคยออฟไลน์ คำทัก/การแตะของสายแรกไม่รอ คำพูดแรกของลูกค้ารอเท่าที่เหลือของการโหลด)

turnlog ที่เกี่ยว: `offline_session` (จำนวนประโยคที่อนุมัติ/ร่าง), `offline_asr` (ภาษา, ms ถอด/แยกภาษา, วินาทีเสียง, จำนวนตัวอักษร — ไม่มีคำ), `offline_route` (เรื่อง/ประโยค/หยุด/เงียบ + หมวดเหตุผล), `net_state`, `dial_backoff`, `offline_fallback`, `offline_end`, `story_shown`

## 6. แนะนำจริงๆ: เราเตอร์ 4G สำรอง

ตัวสำรองออฟไลน์คือ "ประคองให้ไม่เงียบ" — ตอบได้แค่เรื่องเล่าและประโยคตายตัว ทางที่ทำให้ Emma **ยังเป็น Emma เต็มตัว** ตอนเน็ตห้องขายล่มคือให้หุ่นไม่ขาดเน็ตเลย:

- **เราเตอร์ dual-WAN ที่ failover อัตโนมัติไป 4G/5G** (ใส่ซิมข้อมูล) ต่อ Wi-Fi ที่หุ่นใช้อยู่ — Wi-Fi ของหุ่นไม่ต้องเปลี่ยน, เลือกรุ่นที่ตรวจ "เน็ตหลุดจริง" ด้วย ping/DNS ไม่ใช่แค่สายหลุด (อาการที่หุ่นน่าจะเจอคือ Wi-Fi ต่ออยู่แต่ไม่มีอินเทอร์เน็ต)
- ปริมาณข้อมูลน้อย: เสียงขึ้นเฉพาะช่วงลูกค้าพูด (PCM 16 kHz ≈ 256 kbit/s) และเสียงลงเฉพาะช่วง Emma พูด (24 kHz ≈ 384 kbit/s) — ประมาณจากรูปแบบเสียง ไม่ใช่การวัดค่าใช้จ่ายจริง แพ็กเกจ 4G ทั่วไปพอ
- ระหว่างสลับเส้นทาง (ไม่กี่วินาที) สายที่คุยอยู่อาจหลุดแล้วต่อใหม่เอง — ตัวต่อใหม่/ตัวสำรองในงานนี้รับช่วงนั้น
- ทำคู่กัน: 4G สำหรับ "เน็ตห้องขายล่ม", ตัวสำรองออฟไลน์สำหรับ "Google ล่ม / ซิมหมด / ทุกอย่างล่ม"

## ข้อค้าง

- เทสต์ทั้งชุด/การวัดในเอกสารนี้ไม่ได้รันบนหุ่น (หุ่นติดต่อไม่ได้วันที่ทำ) — RTF/RAM บนหุ่นเป็นการประมาณ
- ตัวจับเรื่องเล่าพลาดสำนวนจริงเยอะ (เมนู 112 ครั้งในตารางจริง) — เติมคำถามจริงในแคตตาล็อกเรื่องเล่า = แก้แคตตาล็อก = อนุมัติใหม่
- ภาษาล็อกเป็นไทยแล้วคนอังกฤษเข้ามา → ส่วนใหญ่เงียบ (เลือกตามแบบที่กำหนด: ไม่แยกภาษาเมื่อรู้ภาษาแล้ว เพื่อประหยัด ~0.3–1 วิต่อประโยค)
- ภาษาที่สาม (จีน ฯลฯ) ตอบอังกฤษ — ไม่มีบรรทัดภาษาอื่น
- **สัญญาอนุญาตของตัวถอดเสียงไทย** (ข้อ 2) — ต้องตัดสินก่อนเปิดบนหุ่น
- สายที่ไม่มีเรื่องเล่า: คำทักออฟไลน์ยังชวนเลือก "สิ่งอำนวยความสะดวกหรือทำเล" — ถ้าจะเปิดสวิตช์บนเครื่องแบบนั้นจริง ต้องมีคำทักอีกแบบ (ยังไม่ได้ร่าง)
