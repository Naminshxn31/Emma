# จาก condo-voice ไปเป็น Jarvis

แผนงาน · 22 สิงหาคม 2026

---

## ข้อสรุปสั้นที่สุด

**คุณสร้าง Jarvis ไปแล้วประมาณ 85%** แค่ยังล็อกไว้ให้คุยแต่เรื่องคอนโด

`condo-voice` ไม่ใช่แค่หุ่นต้อนรับ — มันคือเอนจิน voice assistant ที่ครบแล้ว:
speech-to-speech ต่อเนื่อง, พูดแทรกได้, หลายภาษา, ระบบเครื่องมือที่เพิ่มฟังก์ชันด้วย
decorator เดียว, คุมไฟ-แอร์ผ่าน IR จริง, ค้นความรู้แบบ hybrid, log ทุกเทิร์น

สิ่งที่หนังมีแต่ของคุณยังไม่มี เหลือแค่ **5 ข้อ** และมีข้อเดียวที่ยาก

| Jarvis ต้องมี | ของคุณตอนนี้ |
|---|---|
| ฟังตลอด เรียกด้วยชื่อ | ❌ ต้องกดปุ่ม Start |
| คุยได้ทุกเรื่อง | ❌ ล็อกไว้ให้ปฏิเสธเรื่องนอกคอนโด (ตั้งใจ) |
| สั่งของในบ้านได้เยอะ | 🔶 มีไฟ + แอร์ ผ่าน Broadlink |
| สั่งคอมได้ | ❌ ยังไม่มี |
| จำเจ้าของได้ | ❌ log มี แต่ไม่ได้เอากลับมาใช้ |
| เสียงเป็นธรรมชาติ ตอบไว | ✅ **มีแล้ว** — ส่วนที่ยากที่สุด |
| พูดแทรกได้ | ✅ **มีแล้ว** |
| ระบบเครื่องมือ | ✅ **มีแล้ว** — `@tool` เพิ่มได้เลย |

## เฟส 0 — คุยกับมันเรื่องอะไรก็ได้ (ครึ่งวัน)

**นี่คือขั้นที่ให้ผลเยอะที่สุดต่อแรงที่ลง** แทบไม่ต้องเขียนโค้ดใหม่

ตอนนี้ `app/prompts.py` มีกฎข้อแรกว่า *ห้ามตอบเรื่องนอกคอนโด แม้จะรู้คำตอบ*
คุณเขียนไว้เองตอนหุ่นไปแนะนำมือถือ Xiaomi ให้ลูกค้า — สำหรับห้องขายมันถูก
สำหรับ Jarvis มันคือสิ่งที่ต้องกลับหัว

สิ่งที่ทำ:

1. เพิ่ม `ASSISTANT_PROFILE` ใน `.env` → `condo` หรือ `jarvis`
2. แยก `app/prompts.py` เป็นสองชุด — ชุด `jarvis` เอากฎห้ามนอกเรื่องออก
   ใส่ชื่อ บุคลิก และรู้ว่ากำลังคุยกับเจ้าของ ไม่ใช่ลูกค้าแปลกหน้า
3. จำกัดเครื่องมือของแต่ละ profile ด้วย `TOOL_GROUPS` ที่มีอยู่แล้ว
   (กรองตอน import module ใน `app/tools/__init__.py` — ไม่ต้องแตะ declarations
   เลย ดีกว่าด้วย: module ที่ไม่ถูกโหลดไม่มีทางรั่วเข้า registry)
   ✅ ทำแล้ว 2026-08-22: `TOOL_GROUPS` ว่าง + profile `emma` = เหลือ `smarthome`
   เขียน TOOL_GROUPS เองเมื่อไหร่ ค่านั้นชนะ profile
4. เปลี่ยนเสียงและชื่อใน `.env`

**ได้อะไร:** จบเฟสนี้คุณพูดกับมันได้ทุกเรื่อง สั่งเปิด-ปิดไฟและแอร์ได้ทันที
ด้วยเสียงธรรมชาติแบบที่มีอยู่แล้ว — แค่ยังต้องกดปุ่มก่อนพูด

✅ **เฟสนี้เสร็จแล้ว 2026-08-22** — `ASSISTANT_PROFILE=emma` ใน `.env` แล้วรีสตาร์ต
prompt ของ emma เบากว่า condo สามเท่า (1,167 ตัวอักษร) ซึ่งช่วย latency ตรงๆ
เพราะ Live API ประมวล system instruction ใหม่ทุกเทิร์น เทสต์ `tests/test_profiles.py`
คุมรอยต่อไว้ 13 ตัว ตัวที่สำคัญสุดคือ default ต้องเป็น condo — เครื่องห้องขาย
git pull แล้วห้ามเปลี่ยนบุคลิกเงียบๆ

**อย่าแตะโค้ด condo ให้พัง** เทสต์ 544 ตัวคือตาข่ายรองรับ รันก่อนและหลังทุกครั้ง

## เฟส 1 — เรียกด้วยชื่อ ไม่ต้องกดปุ่ม (2–3 วัน)

คุณเขียนไว้เองใน README ว่านี่คือข้อที่ *"คิดเป็นเงิน ไม่ใช่แค่ความสะดวก"* —
เปิด session ทิ้งไว้ทั้งวันในห้องว่างคือเผา quota เปล่า **wake word คือสิ่งที่ทำให้
"เปิดตลอดเวลา" เป็นไปได้จริงทางการเงิน** ไม่ใช่แค่ทางความสะดวก

**ใช้ `openwakeword`** — ฟรี ทำงานออฟไลน์ทั้งหมด กิน CPU น้อย และ**มีโมเดล
`hey_jarvis` สำเร็จรูปมาให้เลย** ไม่ต้องเทรนเอง

```
pip install openwakeword
```

สถาปัตยกรรมที่ควรเป็น:

```
ไมค์ ──▶ openwakeword (ในเครื่อง, ฟรี, ไม่ส่งเสียงออกเน็ต)
              │ ได้ยิน "Hey Jarvis"
              ▼
         เปิด WebSocket ──▶ ของเดิมทั้งหมดทำงานตามปกติ
              │
              └── เงียบเกิน IDLE_TIMEOUT_S → ปิด session
```

จุดสำคัญ: **เสียงไม่ออกจากเครื่องจนกว่าจะได้ยินชื่อ** ทั้งเรื่องเงินและเรื่องความเป็นส่วนตัว
ได้จากข้อนี้ข้อเดียว

`IDLE_TIMEOUT_S` ที่คุณมีอยู่แล้วคืออีกครึ่งของกลไก — เปิดเมื่อเรียก ปิดเมื่อเงียบ

ทางเลือกอื่น: Picovoice Porcupine มี keyword `jarvis` ในตัวเช่นกันและแม่นมาก
แต่ tier ฟรีจำกัดจำนวนผู้ใช้ ส่วน openWakeWord เป็น Apache-2.0 ไม่มีเงื่อนไข

## เฟส 2 — สั่งของได้จริง (1–2 สัปดาห์ ทำทีละอัน)

ตรงนี้คือที่ที่ "สั่งได้ทุกอย่าง" เกิดขึ้นจริง เพิ่มทีละ tool ใน registry ที่มีอยู่

### ก. ของในบ้าน — ต่อ Home Assistant คือทางลัดที่คุ้มที่สุด

Broadlink IR ที่คุณมีคุมได้เฉพาะของที่ใช้รีโมทอินฟราเรด ของ WiFi (Tuya, ปลั๊กอัจฉริยะ,
หลอด Zigbee, ม่านไฟฟ้า, กล้อง) คุมไม่ได้

แทนที่จะเขียน integration ทีละยี่ห้อ — **ลง Home Assistant แล้วเขียน tool เดียว**

```python
@tool(name="home_control",
      description="สั่งอุปกรณ์ในบ้าน เช่น เปิดปิดไฟ ม่าน ทีวี ปลั๊ก",
      tags=["smarthome"])
async def home_control(entity_id: str, action: str, value: str | None = None) -> dict:
    # POST /api/services/{domain}/{service}  ไปที่ Home Assistant
```

tool เดียวเปิดประตูสู่อุปกรณ์เป็นพันรุ่น และ Home Assistant จัดการเรื่อง
pairing/protocol ให้หมด **ของเดิมยังอยู่** — Broadlink ใช้กับของที่ HA ไม่รู้จัก

### ข. สั่งคอมพิวเตอร์

- เปิดโปรแกรม / เปิดเว็บ / พิมพ์งาน → PowerShell subprocess
- อ่านหน้าจอ / คลิก → `pyautogui` + ส่งภาพให้โมเดลดู
- สั่งงาน Claude ต่อ → เรียก Claude API หรือ Claude Code เป็น subprocess

⚠️ **`confirm=True` ยังไม่มีจริง — ต้องสร้างก่อนถึงจะแตะข้อนี้ได้**
ใน `registry.py` ฟิลด์นี้เขียนไว้ตรงๆ ว่า *"Reserved for a confirmation step;
currently informational"* — มันเป็นธงเปล่า ไม่มีโค้ดบรรทัดไหนอ่านมัน
ตั้ง `confirm=True` วันนี้แล้วสั่ง "ลบไฟล์" มันลบเลย โดยคนเขียนเข้าใจว่ามีด่านอยู่
ซึ่งแย่กว่าไม่มีด่าน เพราะไม่มีใครไประวังแทน

ที่มันยังว่างไม่ใช่ความบังเอิญ: งานนี้ถูก**สั่งพักไว้**ในโปรไฟล์ condo
เพราะการบังคับยืนยันชนกับกฎ "เรียกเครื่องมือทันทีโดยไม่ต้องถามซ้ำ" ของห้องขาย
พอแยก `ASSISTANT_PROFILE` แล้วข้อขัดแย้งนี้หายไปเอง — condo ไม่ยืนยัน (ตามกฎเดิม),
jarvis บังคับยืนยันกับทุก tool ที่ย้อนไม่ได้ ก่อนเพิ่ม tool สั่งคอมตัวแรก
"ลบไฟล์" ที่ฟังผิดเป็น "ลบไฟล์" จริงๆ คือความแตกต่างระหว่างของเล่นกับอุบัติเหตุ

### ค. ปฏิทิน อีเมล งาน

Google Calendar API + Gmail API → tool ละตัว
`get_schedule`, `create_event`, `read_email`, `draft_email`

### ง. เตือนความจำ นาฬิกาปลุก จับเวลา

ง่ายที่สุดในกลุ่มนี้ ทำก่อนได้เลยถ้าอยากเห็นผลเร็ว

ข้อเดียวที่ห้ามพลาด: ตอนปลุก **ห้ามยิง `send_text` ตรงๆ ต้องผ่าน
`events.announce(text, source="alarm")`** นาฬิกาดังตอนไหนก็ได้ รวมถึงกลาง
ประโยคที่หุ่นกำลังพูด — ข้อความที่เข้าไปตอนมีเสียงค้างคือการพูดแทรก โมเดลจะ
ทิ้งเสียงที่เหลือ บั๊กนี้เกิดแล้วสองที่ (ตัวกระตุ้นทัวร์, หุ่นเดินถึง) ท่อกลาง
สร้างไว้แล้วใน `app/events.py` — รอคิวเสียง เช็คซ้ำ และเข้าคิวให้เอง

### จ. ค้นข้อมูลของเรา

ครึ่งหนึ่งของงานนี้เสร็จแล้วโดยไม่รู้ตัว — แต่ครึ่งเดียว:
`retrieval.py` (tokenizer ไทย, BM25, SemanticIndex, RRF) เป็นของกลางจริง
ส่วน `slide_search.py` **ผูกกับสไลด์ทั้งตัว** — มันรู้จัก `title_th`/`keywords_th`,
กดคะแนนเด็คคู่แข่ง, และเรียก `project_knowledge` ของโครงการ
งานจริงคือเขียน index บางๆ ตัวใหม่ทับ `retrieval.py` สำหรับโฟลเดอร์เอกสาร
ไม่ใช่ชี้ path แล้วจบ — ยังเป็นงานครึ่งวันอยู่ แต่คนละแบบกับที่เคยเขียนไว้

### ฉ. ค้นเว็บ

Jarvis ต้องรู้เรื่องวันนี้ ไม่ใช่แค่เรื่องที่โมเดลจำได้ — เพิ่ม tool ค้นเว็บ

## เฟส 3 — ความจำ (3–5 วัน)

ความต่างระหว่าง "ผู้ช่วยเสียง" กับ "Jarvis" คือ **มันจำคุณได้**

คุณมี `data/logs/*.jsonl` อยู่แล้ว — หนึ่งบรรทัดต่อเทิร์น สิ่งที่ขาดคือเอากลับมาใช้:

1. `data/memory.json` — ข้อเท็จจริงถาวรเกี่ยวกับเจ้าของ (ชื่อคน อุปกรณ์ ความชอบ
   ตารางประจำ) ต่อท้าย system prompt ทุกครั้ง เหมือนที่ `condo_facts.json` ทำอยู่
2. tool `remember(fact)` — ให้มันบันทึกเองเมื่อคุณบอกอะไรใหม่
3. ค้นบทสนทนาเก่าด้วย embeddings ที่มีอยู่แล้ว → "เมื่อวานเราคุยเรื่องอะไร"

**กฎเดิมของคุณยังใช้:** ห้ามแต่งข้อเท็จจริง ถ้าไม่มีในความจำต้องบอกว่าไม่รู้

**และแยกที่เก็บให้ขาดตั้งแต่วันแรก:** `data/memory.json` ของ jarvis ห้ามปน
กับ `data/logs/` ของห้องขาย สองอย่างนี้หน้าตาคล้ายกันแต่ชะตากรรมตรงข้าม —
log ห้องขายคือคำพูดของคนแปลกหน้า มีนโยบายลบใน 30 วัน ส่วนความจำ jarvis
คือข้อมูลของเจ้าของเอง ตั้งใจเก็บถาวร ปนกันเมื่อไหร่ วันที่ระบบลบ log ตามอายุ
มันจะลบความจำของคุณไปด้วย หรือแย่กว่า: ความกลัวลบผิดทำให้ไม่มีใครกล้าลบเลย
แล้วนโยบาย 30 วันของลูกค้าก็ตายเงียบๆ

## เฟส 4 — ฮาร์ดแวร์ ให้มันอยู่ในบ้านจริง (ตามงบ)

รันบนพีซีก่อนได้เลยทั้งหมด เอาไว้ค่อยทำตอนใช้จริงแล้วติดใจ

**ไมโครโฟนคือตัวตัดสินคุณภาพ ไม่ใช่ซอฟต์แวร์** — คุณเขียนไว้เองใน README ว่า
ลำโพงตัวเองป้อนเข้าไมค์ตัวเองจะถูกอ่านว่า "คนพูดแทรก" ทุกประโยค นั่นคือปัญหาจริง

- **ReSpeaker Mic Array v2.0** — 4 ไมค์ มี AEC + beamforming ในฮาร์ดแวร์
  รับเสียงข้ามห้องได้ ตัวนี้แก้ปัญหาข้างบนที่ต้นทาง
- ถ้าเอาถูกก่อน: ลำโพง Bluetooth ที่มีไมค์ + `HALF_DUPLEX=true` (คุณมี flag นี้แล้ว)
  แลกกับการพูดแทรกไม่ได้
- หลายห้อง: Raspberry Pi 5 + ReSpeaker ห้องละตัว ยิง WebSocket มาเซิร์ฟเวอร์เดียว
  โปรโตคอลของคุณรองรับอยู่แล้ว

⚠️ **ก่อนออกจากเครื่องตัวเอง ต้องปิด `/ws` ก่อน** README ข้อ "Robot-to-server
authentication" ใช้กับ Jarvis เหมือนกัน — ตอนนี้ใครก็ต่อเข้าพอร์ตได้
บน LAN บ้านพอทน แต่ไม่ทนถ้าเปิดออกเน็ต

## ลำดับที่แนะนำ

```
เฟส 0  ครึ่งวัน   → คุยได้ทุกเรื่อง + คุมไฟแอร์      ★ เริ่มที่นี่
เฟส 1  2-3 วัน    → "Hey Jarvis" ไม่ต้องกดปุ่ม        ★ ตัวที่ทำให้รู้สึกเหมือนหนัง
เฟส 2ง 1 วัน      → เตือนความจำ นาฬิกาปลุก
เฟส 2ก 2-3 วัน    → Home Assistant → คุมทั้งบ้าน
เฟส 2จ ครึ่งวัน   → ค้นเอกสารส่วนตัว (โค้ดมีแล้ว)
เฟส 3  3-5 วัน    → ความจำ
ก่อน 2ข ครึ่งวัน  → confirm=True ให้เป็นของจริง + ปิด /ws ด้วย token
เฟส 2ข 3-4 วัน    → สั่งคอม (ทำทีหลัง เพราะต้องระวังที่สุด)
เฟส 4  ตามงบ      → ไมค์ดีๆ + หลายห้อง
```

**สองบรรทัด "ก่อน 2ข" ไม่ใช่ของแถม แต่เป็นเงื่อนไขของ 2ข เอง**
คำเตือนเรื่อง `/ws` ไม่มี auth เดิมอยู่ในเฟส 4 (ตามงบ, ทำทีหลัง) ขณะที่ 2ข
มาก่อนเฟส 4 ในลำดับนี้ — แปลว่าตามแผนเดิมจะมี WebSocket ที่ใครก็ต่อได้
และรัน PowerShell บนเครื่องได้ เดินอยู่หลายวันก่อน auth จะเกิด
auth ไม่ใช่เรื่องฮาร์ดแวร์ มันแค่ไปอยู่ผิดเฟส

**เฟส 0 + เฟส 1 รวมกันไม่ถึงสัปดาห์ และนั่นคือ 80% ของความรู้สึก "เหมือน Jarvis"**
ที่เหลือคือเพิ่มความสามารถทีละอย่างไปเรื่อยๆ

## เรื่องเงิน

Gemini Live tier ฟรีมีเพดานรายวัน ถ้าเปิด session ทิ้งไว้ 24 ชม. จะเกินแน่นอน
**wake word คือสิ่งที่ทำให้เรื่องนี้จบ** — วันหนึ่งคุณคุยกับมันจริงๆ ไม่กี่นาที

`scripts/what_guests_ask.py` ที่คุณมีอยู่รายงานนาทีต่อวันได้แล้ว ใช้มันวัดของจริง
ก่อนตัดสินใจว่าต้องขยับไป tier เสียเงินไหม
