# การสร้างท่าเอง: คำสั่งที่มีและสิ่งที่ต้องผูกกับหุ่นจริง

วันที่ 11 กันยายน 2026 — วิเคราะห์คู่มือและโค้ด Aobo ที่สำรองไว้ ไม่ส่งคำสั่ง ไม่ต่อพอร์ต ไม่ติดตั้งโปรแกรมหรืออัปโหลดท่าลงหุ่น

## คำตอบ

สร้างท่าเองได้ในระดับรูปแบบคำสั่ง เพราะมีทั้งคำสั่งตำแหน่งรายช่องและการเรียกกลุ่มท่า แต่การทำท่าโบกมือ/จับมือที่ถูกต้องกับหุ่นจริงยังต้องมี channel map และขอบเขตข้อต่อ ไม่จำเป็นต้องรู้เลขท่าจับมือเดิมถ้าจะสร้างลำดับใหม่จากรายช่อง

มีสองทาง: ให้ Emma เก็บและส่งลำดับตำแหน่งเอง หรือใช้เครื่องมือบอร์ดบันทึกเป็นกลุ่มท่าแล้วเรียกตามเลข ทั้งสองทางยังไม่ได้ทดสอบบนฮาร์ดแวร์ของผู้ใช้

## 1. คำสั่งแต่ละชั้นควบคุมอะไร

`n` คือช่องเซอร์โว, `p` คือค่าตำแหน่งตามโปรโตคอล, `t` คือเวลาการเคลื่อน, `g` คือเลขกลุ่ม และ `c` คือจำนวนรอบ อักษรในวงเล็บแหลมด้านล่างเป็น placeholder ไม่ใช่ข้อความที่ส่งจริง

| รูปแบบ | ความหมาย | หลักฐาน/ข้อจำกัด |
| --- | --- | --- |
| `#<n>P<p>T<t>\r\n` | กำหนดตำแหน่งหนึ่งช่องพร้อมเวลา | คู่มือ Torobot หน้า 6; ใน Aobo พบรูปจริง `#<n>P1500T3000` ใน helper PowerOn |
| `#<n1>P<p1>#<n2>P<p2>T<t>\r\n` | กำหนดหลายช่องให้เคลื่อนพร้อมกัน ใช้ T ร่วมหนึ่งค่า | คู่มือ Torobot หน้า 6; ยังไม่ทดสอบหลายช่องบนบอร์ดเครื่องนี้ |
| `#<g>GC<c>\r\n` | เรียกกลุ่มท่าที่บันทึกไว้ c รอบ | Aobo มีทั้ง GC1 และ GC5; เลขกลุ่มไม่ใช่เลขช่องเซอร์โว |
| `#<g1>G#<g2>GC<c>\r\n` | เล่นหลายกลุ่มตามลำดับ | คู่มือ Torobot หน้า 6; ยังไม่ยืนยันเส้นทางนี้ผ่าน Aobo/บอร์ดจริง |
| `#STOP\r\n` | ส่งคำสั่งหยุดตามโค้ดแอป | พบคำสั่งและ parser ACK; ยังไม่พิสูจน์ผลหยุดจริง/ตัดไฟ |
| `#<n>P0T1000\r\n` | helper ที่ Aobo เรียกว่า ReleaseForce | ไม่ใช่ตำแหน่งปกติหรือคำสั่งคงท่า |
| `#99GC1\r\n` | เรียกกลุ่ม 99 ที่แอปใช้กลับท่าตั้งต้น | เคลื่อนไหวได้ ไม่ใช่ stop; พบตอน usbInit และบางเส้นทางหลัง ACK |

ตัวอย่าง **อ่านความหมายเท่านั้น** จาก helper ของ Aobo: `#1P1500T3000\r\n` หมายถึงส่งเป้าหมาย 1500 ให้ช่อง 1 โดยกำหนดเวลา 3000 ms ไม่ใช่ “ยกไหล่ซ้าย 90 องศา” เพราะยังไม่รู้ช่อง 1 ต่อกับอะไร และไม่มีตารางแปลงค่า P เป็นมุมจริง

คู่มืออ้างอิงระบุ P ช่วง 500–2500, T ช่วง 100–9999 และปิดท้าย CRLF ไม่มีช่องว่าง เป็นขอบเขตโปรโตคอล ไม่ใช่ขอบเขตที่ปลอดภัยของทุกข้อต่อ ไม่ใช้ 1500 เป็นท่ากลางที่รับรองแล้ว และไม่สรุปว่าเวลาที่ยาวขึ้นป้องกันการชน/แรงกดได้

## 2. คู่มือสร้างและบันทึกกลุ่มท่าที่พบ

คู่มือหุ่นที่ผู้ใช้ส่ง หน้า 6 ระบุใช้ Torobot programming software ส่วนคู่มืออ้างอิง `torobot-usc_en.pdf` มีขั้นตอนชัดเจน:

- หน้า 4: ตั้งตำแหน่งหลายช่องกับเวลา แล้วใช้ **Add** เก็บเป็นหนึ่งขั้น สร้างหลายขั้นเป็นลำดับเดียวกัน
- หน้า 4: **Download** เขียนกลุ่มท่าลงบอร์ด แล้วโปรแกรมแจ้งหมายเลขกลุ่มที่บันทึก
- หน้า 5: **Read** แสดงหมายเลขกลุ่มที่มี, Run เรียกกลุ่ม, มีโหมด offline และคำสั่งล้าง Flash
- หน้า 6: รูปแบบคำสั่งตำแหน่งและการเรียกกลุ่มตามตารางด้านบน

นี่เป็นความสามารถตามคู่มืออ้างอิง ไม่ใช่ผลว่า RIOS_USC เชื่อมกับบอร์ดเครื่องนี้สำเร็จ หน้าตัวอย่างใช้บอร์ด 32 ช่องและค่า baud 9600 ขณะที่คู่มือหุ่นกล่าวถึง 20 ช่องและโค้ด CH340 ตั้ง 115200 จึงไม่เปลี่ยน baud หรือเปิดโปรแกรมตามค่าตัวอย่างโดยอัตโนมัติ

ยังไม่พบรูปแบบ packet สำหรับ upload/read-back เนื้อหากลุ่มจากแหล่งที่ตรวจ ห้ามอนุมานว่า Read แสดงหมายเลขกลุ่มเท่ากับอ่าน keyframe ทั้งหมดหรือสำรอง Flash ได้ ส่วน Download/Erase เป็นการเขียนข้อมูล ไม่ได้ทำในงานนี้

## 3. ปุ่ม Save ใน Aobo ไม่ใช่การบันทึก keyframe

`ArmTestActivity.onClick` branch ที่เริ่มที่ instruction offset 0xb2 นำ `voiceArmKeyWordBeans` ไปแปลง Gson JSON แล้วเขียน SharedPreferences `armkeywordsharepreferences`, key `armkeywordJson` ด้วย `commit()` จากนั้นอัปเดตรายการใน MyApplication

ข้อมูลใน bean ได้แก่คำพูด `keyWord`, เลขที่ผูก `bindvalue`, ชื่อ `actionName`, ชนิด `actionType`, ไฟล์สื่อ `saveMusicPath` ไม่ใช่รายการตำแหน่งเซอร์โวและเวลาของแต่ละขั้น การกด Save ในส่วนคำพูดของหน้า Arm Test จึงไม่ใช่หลักฐานว่าสร้างท่าใหม่ในบอร์ดแล้ว

ตัวส่ง CH340 `startAction(byte[])` ส่ง bytes ต่อ แม้ชื่อเมธอดเป็น Action โดยใช้ `extractNumberWithDefault` เพื่อบันทึกเลขกลุ่มในสถานะแอป; ถ้าไม่พบรูป `#...GC` จะใช้ 99 เป็นค่า metadata ไม่ได้แปลว่าแทนเฟรมที่ส่งเป็นกลุ่ม 99 ดังนั้นสถานะ `currentArmAction=99` อย่างเดียวใช้สรุปคำสั่งที่ส่งจริงไม่ได้

## 4. ข้อมูลที่ต้องมีต่อหนึ่งข้อต่อ

| ข้อมูล | สถานะปัจจุบัน |
| --- | --- |
| ช่องควบคุม | พบตัวเลือก 1, 11, 7, 8; ไม่ใช่หลักฐานว่ามีเพียงสี่ข้อต่อ |
| ชื่อและตำแหน่งข้อต่อจริง | ยังไม่ทราบ |
| ทิศทางเมื่อเพิ่ม/ลด P | ยังไม่ทราบ |
| ค่า P ต่ำสุด/สูงสุดและท่าพักที่ใช้ได้ | ยังไม่ทราบรายข้อต่อ |
| ตำแหน่งที่วัดได้ขณะเริ่ม | ยังไม่มี feedback ที่ยืนยัน |
| ส่วนที่เคลื่อนพร้อมกันได้โดยไม่ชน | ยังไม่ทราบ |
| วิธีหยุดที่มีผลจริงและพฤติกรรมหลังหยุด | พบโค้ดรองรับ แต่ยังไม่ทดสอบฮาร์ดแวร์ |

วิเคราะห์ไฟล์ช่วยบอก syntax และเส้นทางส่งได้ แต่ไม่สามารถคำนวณการต่อสายที่ไม่มีอยู่ในข้อมูลได้ ต้องได้หลักฐานการต่อสาย/ตารางจากบอร์ด/การสังเกตเครื่องจริงก่อนเติมชื่อข้อต่อ การทดสอบเคลื่อนไหวไม่รวมอยู่ในการอนุญาตค้นข้อมูลรอบนี้

## 5. รูปแบบท่าของ Emma ที่ออกแบบได้

หนึ่งท่าเป็นลำดับของ **เป้าหมายรายช่อง + เวลาเคลื่อน + เวลาค้าง** เช่นท่าโบกมือมีขั้นเตรียมแขน ยกแขน แกว่งกลับไปมา และกลับท่าพัก ขณะนี้ชื่อขั้นเป็นเพียงเจตนาของท่า ยังไม่ใส่ค่าตำแหน่งตัวเลขให้ดูเหมือนพร้อมใช้

หลังได้ mapping จึงผูกแต่ละขั้นกับช่องและขอบเขตจริง เก็บเป็นไฟล์ใน Emma และตรวจลำดับบนคอมก่อน การรอครบ T หรือสถานะ write สำเร็จไม่เท่ากับวัดว่าข้อต่อถึงเป้าหมายแล้ว และท่าจับมือคนต้องมีข้อกำหนดแรง/การสัมผัสเพิ่มเติมจากลำดับตำแหน่งอย่างเดียว

ทางที่ให้ Emma เก็บ keyframe เองยังไม่ต้องเขียน Flash บอร์ด แต่ต้องยืนยันว่าบอร์ดรับลำดับรายช่องได้และช่องทางส่งไม่ถูกแอปเดิมแทรก ส่วนการเก็บในบอร์ดต้องยืนยันวิธี upload และป้องกันทับกลุ่มเดิมก่อน ไม่เลือกเลขว่างด้วยการเดา

## 6. พบพฤติกรรมกลับท่าหลัง stop ACK ที่ต้องนับรวม

ไล่โค้ดเพิ่มพบ:

1. `SerialToothManagerCH340.handleCompletePacket()` ตรวจข้อความมี `#STOP+OK`, สร้าง int[] ยาวตาม packet ที่รับ และส่ง Handler message 3131
2. `SerialdataService$2.handleMessage()` branch FROMARM ถ้า array ยาว **13** จะเรียก `read32UartControlStopARM()` (ความยาวอื่นอาจไม่เข้า branch นี้)
3. `read32UartControlStopARM()` ถ้า `isArmBlocked=true` จะคืนทันที แต่ถ้า false จะส่ง **`#99GC1`** และ schedule ส่งกลุ่ม 99 ซ้ำหลัง 120 ms ผ่าน `SerialdataService$6`

นี่เป็นเส้นทางในโค้ดที่ตรวจ ไม่ใช่การรายงานว่าหุ่นขยับจริงหลัง stop ในการทดลอง และไม่ควรสรุปว่า ACK ทุกแบบเรียก reset เสมอ อย่างไรก็ตามการออกแบบ Emma ให้ส่ง stop แล้วถือว่าระบบทั้งหมดหยุดส่งคำสั่งต่อไปต้องคำนึงถึง Aobo ด้วย ล็อกเฉพาะ Emma ไม่ล็อกพฤติกรรมของแอปเดิม
