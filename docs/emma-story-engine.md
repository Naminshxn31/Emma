# Emma เล่าเรื่องด้วยภาพ — Interactive Presentation Engine

ลูกค้าถาม → Emma ตอบด้วยเสียง และจอหน้าหุ่นเล่าเรื่องเดียวกันเป็นภาพเคลื่อนไหว **ทีละจังหวะตามเสียงที่ลำโพงเล่นอยู่จริง**
แล้วจบที่ภาพรวมที่ลูกค้าแตะต่อได้ (คำสั่งเจ้าของ 12 ต.ค. 2026) ต้นแบบที่เจ้าของดูแล้วคือทิศทางของภาพ
ตัวเล่นเรื่องสร้างครั้งเดียว เรื่องต่อไปเป็นแค่ข้อมูล: ภาพ คำพูด คำที่ใช้จับจังหวะ และจุดบนภาพ

| ส่วน | ไฟล์ |
|---|---|
| เซิร์ฟเวอร์ (แคตตาล็อก การอนุมัติ ภาพ payload คำที่ปุ่มแตะส่ง) | `app/stories.py` |
| เครื่องมือ `present_story(topic)` | `app/tools/stories.py` (กลุ่ม `stories`) |
| ตัวเล่นบนหน้าหุ่น (นาฬิกาจังหวะ + 9 แม่แบบ) | `client/assets/emma-story.js`, `client/assets/emma-story.css` |
| ต่อเข้าหน้าหุ่น | `client/voice-preview.html` (`storyHook`, `showStory`) |
| ภาพ `/story-asset/<sha256>` | `app/main.py` |
| ตัดภาพ + สร้างแคตตาล็อก | `scripts/build_story_assets.py` |
| อนุมัติ (คนเท่านั้น) | `scripts/approve_stories.py --by "ชื่อ"` |
| เล่นทุกเรื่องโดยไม่ต้องมี Gemini (วิดีโอ เฟรม จังหวะ fps) | `scripts/record_stories.py` |
| เรื่องตัวอย่าง 1 เรื่องต่อแม่แบบ และต่อ view (`VIEW_STORY`) (ภาพวาดเอง ใช้ในเทสต์) | `scripts/story_fixture.py` |

## กติกาที่ห้ามหลุด (ทุกข้อคือบั๊กหรือคำสั่งเจ้าของที่เคยเกิดจริง)

1. **โมเดลเลือกได้แค่ "เรื่องไหน"** — `present_story(topic)` รับ `topic` ตัวเดียวเป็น enum ของเรื่องที่อนุมัติ
   ตัวเลข คำ และภาพทุกชิ้นมาจากแคตตาล็อก แบบเดียวกับ `show_unit(room)` (มีเทสต์ยันว่าพารามิเตอร์มีแค่ topic)
2. **ปิดเป็น default สองชั้น** — `STORIES_ENABLED=false` และกลุ่ม `stories` เป็น opt-in (TOOL_GROUPS ว่างไม่โหลด)
   เห็นเฉพาะเซสชันของหน้าหุ่นเอง (`robot_face_session`) โปรไฟล์ condo และแคตตาล็อกอนุมัติแล้วมีเรื่องครบอย่างน้อยหนึ่งเรื่อง
   ปิดอยู่ = เครื่องมือ คำอธิบาย และ prompt ของห้องขายเหมือนเดิมทุกไบต์ (snapshot P0/P6 ผ่านโดยไม่ต้องสร้างใหม่)
3. **ห้ามเลือกโดยปริยาย (deny by default)** — แคตตาล็อกมีหกช่องอนุมัติที่ `evaluate_claim` ตรวจ + `approved_sha256`
   (digest ของเรื่องทั้งหมดและหมุดภาพ ณ ตอนที่คนอนุมัติ) แก้อะไรหลังอนุมัติ = กลับเป็น draft ทันที
   build ทุกครั้งเขียนเป็น draft เสมอ (ยกเว้นเนื้อหาเหมือนเดิมเป๊ะ) **ไม่มีโค้ดไหนเขียน `approved_by` แทนคน**
4. **ภาพปักด้วย sha256 และ hash ซ้ำตอนเสิร์ฟ** — ภาพหาย/เปลี่ยน = เรื่องนั้นไม่ถูกเสนอเลย (ครึ่งเรื่องคือจอพัง)
   `/story-asset/` อยู่หลัง WS_TOKEN แบบเดียวกับ `/unit-plan/` และเสิร์ฟเฉพาะแคตตาล็อกที่อนุมัติ + สวิตช์เปิด
5. **ห้ามราคา ห้ามคำที่เจ้าของห้าม** — เรื่องที่มีราคา (สกุลเงิน "ล้าน" หรือคำว่าราคาตามด้วยตัวเลข),
   "แนวคิดเบื้องต้น / อาจมีการเปลี่ยนแปลง", "ไม่มีข้อมูล/ไม่ทราบ", Rooftop, Thermal Galaxy, อู่ตะเภา 40–60 นาที
   ถูกปฏิเสธทั้งเรื่องตอนโหลด · คำว่า "ไม่รวมในราคาห้อง" (ชุด Smart Home เป็นแพ็กเกจเสริม) **พูดได้** เพราะไม่มีตัวเลข
   ภาพที่ต้นทางชื่อ quotation/rooftop/thermal galaxy ถูกปฏิเสธทั้งตอน build และตอนเสิร์ฟ (ใบเสนอราคามีราคา)
6. **ภาพตามเสียง ไม่นำเสียง** — ข้อความมาเร็วกว่าเสียง 4–6 เท่า จังหวะจึงผูกกับ **เสียงที่เล่นไปแล้วจริง**
   (หน้าเว็บรู้ว่าตัวเองตั้งเวลาเสียงแต่ละชิ้นไว้ตอนไหน) ไม่ใช่กับเวลาที่ข้อความมาถึง
7. **ลูกค้าพูด/แตะแทรก = ข้ามไปฉากจบทันที ไม่มีภาพขยับ** · `prefers-reduced-motion` = ฉากจบเลย
8. **คำของลูกค้าไม่ขึ้นจอหุ่น** — ตัวเล่นได้รับแค่ transcript ของ Emma กับเวลาเสียง ไม่มีทาง (และไม่มีโค้ด) รับ `user_transcript`
9. **ไม่มีวงแสงหลังหรือใต้ Emma** (เจ้าของสั่งเอาออกสองครั้ง) วงมีได้เฉพาะบนภาพเพื่อชี้จุด และกระพริบแค่สองครั้งแล้วหยุด
10. **เบาพอสำหรับหุ่น** — ขยับแค่ `transform` / `opacity` (+ ตัวเลขนับขึ้นหนึ่งโหนด) ไม่มี backdrop-filter / filter / blur /
    box-shadow ที่ขยับ / clip-path / width/height ที่ขยับ ไม่มี animation infinite · ภาพย่อมาพอดีจอ (≤250 KB) และ decode
    ก่อนถึงจังหวะของมัน · เล่นทีละเรื่อง เรื่องใหม่หรือภาพอื่นบนเวที = รื้อเรื่องเก่าและปล่อยภาพทิ้ง (เทสต์ตรวจ CSS/JS) · วัด 21 ต.ค.: **ห้าม box-shadow ที่เบลอ** (รายการแบบห้อง p95 33 ms วินาทีแย่สุด 38 fps) และ**ห้ามซูมภาพข้างในกรอบ** (Sky Pool วินาทีแย่สุด 59 → 47 fps) — เอาออกทั้งคู่
11. **แต่ละคำตอบเป็นเจ้าของจอ** — เรื่องอยู่บนจอจนคำตอบถัดไปของลูกค้าเปลี่ยนจอ (คำตอบที่ไม่มีภาพ = ล้างตอน turn_complete
    เหมือนเดิม) · ถ้าคำตอบเดียวกันมีภาพ ANSWER_IMAGES จาก `search_condo_info` ด้วย **เรื่องชนะ** (`storyOwns`)
12. **ปุ่มแตะส่งแค่ id** — ผ่านประตู `quick_ask` เดิม รับเฉพาะ id ของเรื่องที่เซสชันนี้เพิ่งขึ้นจอ (`_story_taps`)
    คำที่ส่งถึงโมเดลเป็นของแคตตาล็อก: "[ลูกค้าแตะปุ่ม ... ไม่ได้พูด] เรียก present_story(topic="...")" หรือเครื่องมืออ่าน/จอ
    ที่อนุญาต (`show_room_type`, `show_plan`, `find_units`, `compare_unit_types`, `search_condo_info`) และต้องมองเห็นอยู่จริง
    ปุ่มที่ไปหาเครื่องมือที่โมเดลมองไม่เห็นไม่ถูกวาด (บั๊ก "ปุ่มชวนแต่โมเดลปฏิเสธ")
13. Emma ย่อลงมุมขวาล่างระหว่างเล่าเรื่อง (`body.emma-story`, ราว 30% ของความกว้าง ตามต้นแบบ) — app shell เดิมให้เธอกว้าง
    610 px ซึ่งจะยืนทับหนึ่งในสามของจอ
14. **แตะรูปไหนก็ได้ = ขยาย + เล่าเพิ่ม** (เจ้าของ 16 ต.ค. "กดรูปบนจอ ... ขยายภาพนั้นและอธิบายเพิ่มเติมจากตอนแรก") —
    `page_payload` ส่ง `zoom` (รูปทุกรูปของเรื่องตามลำดับแคตตาล็อก: src, ป้ายจากแคตตาล็อก, id `story_<เรื่อง>_more_<n>`;
    เฟรมโฮโลแกรมของ assembly ไม่นับ) · หน้าเลือกรูปที่**มองเห็น**บนสุดใต้นิ้ว (`elementsFromPoint` + ความทึบ — รูปถัดไปรอ
    opacity 0 ทับอยู่) ขยายทันทีในหน้า (ขนาดตามที่ว่าง สัดส่วนเดิม แตะอีกครั้งปิด) · รูปในแถว/ชั้น/การ์ดที่มีเรื่องของตัวเอง
    ส่ง tap ของแถวนั้น (bindTap) ไม่ส่งซ้ำ · รูปอื่นส่ง more tap พร้อม `keep` → เรื่อง+ภาพขยายเป็นจอของคำตอบนั้น (หน้า
    answerStaged/storyOwns, เซิร์ฟเวอร์ `_screen_staged`/`_story_owns_answer`) · ข้อความ more = ป้ายรูป + ข้อความจากรายงาน
    (`project_report.search`: ป้ายก่อน แล้วป้าย+คำถามของเรื่อง แล้วคำถาม — ข้อละหนึ่งท่อน) + ประโยคที่เพิ่งเล่า (ห้ามพูดซ้ำ) +
    กฎเดียวกับผลค้นรายงาน ไม่เรียกเครื่องมือ · ตรวจ: `record_stories.py --tap-pictures` คลิกจริงทุกรูปที่เห็นตอนจบเรื่อง

## รูปแบบไฟล์

ทุกอย่างอยู่ใต้ `data/projects/<project>/stories/`

```
recipes/*.json    วิธีตัดภาพแต่ละภาพจาก .tmp/story-sources (tracked, เล็ก)
design/*.json     เรื่อง (tracked) — ไฟล์ละหนึ่งเรื่อง, list, หรือ {"stories": [...]}
asset_pins.json   หมุดภาพ (สร้างโดย build, tracked)
stories.json      แคตตาล็อกที่เซิร์ฟเวอร์อ่าน (สร้างโดย build, tracked) — draft จนกว่าคนอนุมัติ
assets/           ภาพที่ตัดแล้ว (gitignore — สร้างใหม่ได้ด้วยคำสั่งเดียว)
```

### recipe

```json
{"id": "fac_g_biogenesis", "source": "web/4.facilities/G FLOOR/G FLOOR - Biogenesis 01.jpg",
 "crop": [454, 0, 2297, 1152], "max_w": 1080, "format": "webp", "why": "..."}
```
- `source` นับจาก `.tmp/story-sources` หรือข้อมูลของโครงการในรีโป (`../../data/projects/<project>/...` — สไลด์ที่อนุมัติ, แปลนรายยูนิต)
- `crop` เป็นพิกเซลของต้นทาง (ตัด UI ที่ UE ฝังมาออก) · PDF ใช้ `"page"` (เริ่ม 1) และ `"dpi"`
- ตัวเลือก: `max_h` (1920), `quality` (82, ลดเองจนไม่เกิน 250 KB), `max_kb`, `source_sha256` (ปักต้นทาง), `post: [...]`:
  `"lines_to_alpha:#bad6ff"` (แปลนเส้นดำพื้นขาว → เส้นสีบนพื้นใส จอวาดบนพื้นมืด) ·
  `"inpaint:x0,y0,x1,y1"` (ลบรอยบางๆ ที่ฝังในภาพ เช่นเส้นชี้ของ callout: แต่ละแถวผสมจากพิกเซลซ้าย-ขวาของกรอบ กว้างไม่เกิน 40 px) ·
  `"fill:x0,y0,x1,y1@sx,sy"` (ระบายสีของพิกเซล sx,sy — ตรงที่รอยพาดตัวอักษร) — พิกัดของ post เป็นพิกเซล**หลังครอป**
- จุด x/y ใน params อ้าง **ภาพหลังตัด** เป็น % (0–100)

### story

```json
{
 "id": "room_types", "template": "stack",
 "questions_th": ["มีห้องแบบไหนบ้าง"], "questions_en": ["What room types are there?"],
 "lines": [{"th": "...", "en": "...", "cue_th": ["สตูดิโอ"], "cue_en": ["studio"], "cue_zh": ["开间"]}],
 "params": { ... ตามแม่แบบ ... },
 "taps": [{"id": "story_room_types_studio", "label_en": "Studio", "label_th": "สตูดิโอ",
           "next_story": null, "tool": {"name": "show_room_type", "args": {"type": "studio"}}}],
 "sources": ["facts:แบบห้องและขนาด", "report:04_location.md#...", "slides:intro-041"],
 "notes_th": "..."
}
```
- `lines` ตามลำดับที่ Emma พูด หนึ่งบรรทัด = หนึ่งจังหวะ (`line: i` ใน params) สูงสุด 12 บรรทัด
- `cue_*` = คำที่เธอ**ต้อง**พูดแน่ในบรรทัดนั้น (ชื่อเฉพาะ คำนาม) **อย่าใช้ตัวเลขหรือคำสั้นที่ไปซ่อนในคำอื่นได้**
  (บทเรียน "ราคา" ใน "อาคาร") · คำของจังหวะถัดไปควรไม่โผล่ในบรรทัดก่อนหน้า
- `sources` ทุกตัวเลขต้องอ้างได้: `facts:<label>` (ข้อมูลโครงการที่อนุมัติ), `report:<ไฟล์>` (เฉพาะบทที่ปักใน
  `sales/project_report_approval.json`), `slides:<id>`, `sales:qa_script.json`, `plans:unit-plans/index.json`
  ส่วน `web:` / `ue:` / `assets:` คือที่มาของภาพ (ไม่นับเป็นแหล่งตัวเลข) — build รายงานตัวเลขที่ไม่พบในแหล่งที่อ้าง
- `taps[].id` ขึ้นต้น `story_` · ต้องมี `next_story` หรือ `tool` อย่างใดอย่างหนึ่ง
- `notes_th`, `sources`, `questions_*` ไม่ถูกส่งให้หน้าเว็บ

### แม่แบบ 11 แบบ (params)

| แม่แบบ | ใช้กับ | params |
|---|---|---|
| `stack` | แบบห้อง: ทีละแบบขึ้นใหญ่ แล้วย่อไปเกาะเป็นแถว จบที่รายการแตะได้ | `items[{label_en, sub_en, asset, asset_kind: plan\|photo, value{from,to,unit_en}\|null, line, tap?}]`, `end_hint_en` — แถวผูกปุ่มเองเมื่อจำนวน taps เท่ากับ items (ตามลำดับ) หรือระบุ `tap` · บรรทัดเปิดที่ไม่มี item ("มีสามแบบ") = แถวว่างรอ ป้ายยังไม่ขึ้นจนเธอพูดถึง |
| `slabs` | ส่วนกลางทีละชั้น: แผ่นชั้นลอยขึ้นเป็นกอง ชั้นที่พูดถึงเรืองแสง | `floors[{label_en, sub_en, asset, line, next_story}]`, `order_bottom_up`, `end_hint_en` — แผ่นผูกปุ่มที่มี `next_story` เดียวกัน |
| `drill` | ในชั้นหนึ่ง (13 ต.ค. ## จังหวะตามเสียง (นาฬิกาใน `emma-story.js`)

- หน้าเว็บรายงานเสียงทุกชิ้นที่ตั้งเวลาเล่น (`playChunk` → `storyHook('audio', at, duration)`) นับเฉพาะเสียงหลังผลเครื่องมือมาถึง
  และส่ง transcript ของ Emma (`assistant_transcript`) — "เสียงที่เล่นไปแล้ว" = ผลรวมช่วงเสียงที่เวลา AudioContext ผ่านไปแล้ว
- จังหวะ 0 = เมื่อเสียงคำตอบเริ่มเล่น · จังหวะ i = เมื่อเสียงที่มีคำ cue ของบรรทัด i เล่นถึง
  · นาฬิกาของหน้าคือ `audioCtx.currentTime` **ลบ** `outputLatency + baseLatency` (เวลาที่เสียงเดินจาก context ถึงลำโพง)
- หาตำแหน่งคำในเสียง: Gemini ส่ง transcript แต่ละชิ้น**ก่อน**เสียงของชิ้นนั้น (วัดจาก eval สด 12 ต.ค.: 91/91 คำตอบเปิดด้วย
  ข้อความ ไม่เคยมีข้อความสองชิ้นติดกันโดยไม่มีเสียงคั่น ~1.4 วิของเสียงต่อชิ้น) → เสียงของชิ้นหนึ่ง "ครบแล้ว" เมื่อมีเสียงตามหลัง
  มันแล้วและชิ้นถัดไปมาถึง (หรือ turn_complete) จึงใช้ยอดเสียงตอนนั้นเป็นขอบบนของจุดจบชิ้น + เผื่อหนึ่งก้อนเสียง (0.12 วิ)
  ย้อนด้วยความเร็วที่ไม่มีใครพูดได้ (20 ตัวอักษร/วิ) = ไม่มีวันเร็วกว่าเสียง · ชิ้นที่เสียงยังไม่ครบ = ยังไม่ยิง
  (เดิมใช้ยอดเสียงตอนข้อความมาถึง = เสียง**ก่อน**หน้าชิ้นนั้น ภาพนำเสียงได้ทั้งชิ้น — รีวิว 12 ต.ค.) · ถ้าข้อความตามหลังเสียง
  แทน วิธีนี้ช้าไปหนึ่งชิ้น ไม่เร็ว · พอคำตอบครบ (turn_complete ของคำตอบนี้ — ไม่นับอันที่ 3.8 ส่งก่อนเรียกเครื่องมือ)
  ใช้อัตราส่วนข้อความ/เสียงของทั้งคำตอบ
- ไม่เจอคำ cue (เธอพูดเรียบเรียงใหม่): ยิงเองเมื่อเลย ~4 วิของเสียงหลังจังหวะก่อน หรือเร็วกว่านั้นถ้าความยาวบรรทัดบอกว่าเธอ
  ต้องอยู่ตรงนั้นแล้ว · ไม่มีเสียงเลย = ไม่มีอะไรขยับ (ไม่มีเสียงเกิน 7 วิ = ขึ้นภาพรวมเงียบๆ)
- เสียงเล่นจบ + คำตอบครบ = จังหวะที่เหลือ แล้วภาพรวม (มีภาพเคลื่อนไหว) · ถูกแทรก = ภาพรวมทันทีไม่มีภาพเคลื่อนไหว
- ทางออกกันค้าง: เสียงเล่นหมดแล้วไม่มีเสียงใหม่ 3 วิ แต่ไม่มี turn_complete (สตรีมหยุด/หมุน session) = ภาพรวม ·
  นาฬิกาเสียงหายหลังเสียงเริ่ม (สายหลุด) 2 วิ = ภาพรวม (และ `ws.onclose` สั่ง settle ทันที) · ไม่มีเสียงเลย 7 วิ = ภาพรวม
- ตัวเลขเดี่ยวนับขึ้น ("≈ 224") · **ช่วง** ("24–29 sq.m.") ขึ้นค่าจริงทันที ไม่นับ — นับสองปลายจาก 0 เคยโชว์ "0–0" และ
  "20–24 sq.m." ค้างบนจอระหว่างที่เธอพูด "24 ถึง 29"
- `stack`: ระหว่างพูด รายการคือแถวเดียวกันย่อด้วย transform ใต้แถบคำพูด การ์ดใหญ่ของแบบถัดไปขึ้น**ใต้**แถวที่เกาะแล้ว
  (รายการโตให้เห็นทีละแถว) ตอนจบรายการขยายเป็นขนาดเต็ม · ป้ายของจุดบนภาพวางห่างวงด้วยความสูงของป้ายเอง (ไม่ใช่ % ของภาพ)
- ภาพที่โหลดไม่ได้ถูกซ่อน (`es-broken`) ไม่โชว์ไอคอนภาพแตก · teardown ไม่ล้าง `src` ของภาพที่ถอดออกแล้ว (Chromium เก็บ DOM
  ของทุกเรื่องค้างไว้ตลอดอายุหน้า ถ้าล้าง — รีวิว 12 ต.ค.)

ผลวัดด้วย harness (เสียงสังเคราะห์ 14 ตัวอักษร/วิ, ลำดับแบบ Gemini: ข้อความแต่ละชิ้น 18 ตัวอักษรมาก่อนเสียงของมัน):
จังหวะขึ้น **หลัง**คำ cue 0.1–0.45 วิ · โหมด `--order trail` (ข้อความตามหลังเสียง) ช้า 0.7–1.3 วิ ไม่เร็วกว่าเสียง ·
ยังไม่เคยวัดกับเสียงจริงบนหุ่น
