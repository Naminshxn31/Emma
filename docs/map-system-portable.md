## แท่นของตัวจำลองตามไฟล์ของวันนี้ (แก้เทสต์แดง)

`test_todays_way_home_docks_from_the_rehearsal_round` แดงหลังวัดแท่นใหม่คืน 19 พ.ย.: ตัวจำลองเขียนแท่น 16 พ.ย. (−7.11, −6.78, 169.6°)
ตายตัว ขณะที่ floor1.json (และหุ่น) ใช้ (−7.04, −6.89, 171.0°) — ห่าง 13 ซม. ตัวจำลองจึงตัดสินว่าหุ่น "เข้าแท่นเยื้อง 10 ซม." ทั้งที่หุ่นนั่งตรงขั้ว

- ตอนนี้แท่นของตัวจำลอง = **ของวันนี้**: ท่าที่ "วัดแท่นใหม่" เขียนไว้ในไฟล์จุดของหุ่น (`floor1_event.spots.json` คีย์ `dock`, อ่านด้วย `event_host._relearnt` ตัวเดียวกับหุ่น)
  ถ้ามี ไม่งั้น floor1.json · `--spots <ไฟล์ที่ดึงจากหุ่น>` = ใช้แท่นในไฟล์นั้น
- การเดินของงานเข้าแท่นตามท่าที่วัดใหม่ (เหมือน `dock_doc` บนหุ่น) · เส้นทางใน floor1.json เข้าแท่นตามท่าในไฟล์ (board_walk อ่านไฟล์ตรง)
  — ถ้าสองค่านี้ต่างกัน preflight พิมพ์บรรทัด `!!` บอกระยะห่าง (และเส้นทางนั้นจะเข้าแท่นเยื้องในตัวจำลอง เหมือนที่จะเกิดบนหุ่น)
- การเล่นซ้ำคืนเก่า (calibrate, เทสต์คืน 16 พ.ย.) ใช้แท่นของคืนนั้น `load_layout(dock="night")`
- **ที่เจอเมื่อย้ายแท่น:** แท่นวันนี้ในเฟอร์นิเจอร์ 16 พ.ย. แขนออกจากแท่นผ่านของในช่องแท่นที่ (−6.97, −7.12) ห่าง ~0.10 ม. ที่ 0.3 ม. แรก
  (เดิม 0.19) — ยังอยู่ในเกณฑ์ 0.05 แต่ช่องแท่นถูกจัดใหม่ 19 พ.ย. ตัวจำลองยังไม่มีเฟอร์นิเจอร์ของคืนนั้น เทสต์ "ออกทาง corridor" จึงวัดที่ห่างแท่น > 0.6 ม.
  (เรื่องที่เทสต์ถาม: โต๊ะที่ (−8.0, −4.8)) และยังถือช่วงใกล้แท่นไว้ที่เกณฑ์ของ preflight

- Emma = ค่าคงที่เดิมทุกตัว (float ตัวเดียวกัน) — `tests/test_robot_profile.py` ผูกค่าในโปรไฟล์กับค่าคงที่ใน robot_lanes / floor_sim / map_check / walk_sim
  แก้ที่หนึ่งไม่แก้อีกที่ = เทสต์แดง

- ได้สเปกจากผู้ขายแล้ว: เขียน JSON (`{"id": "vendor_x", "body": {...}, "lidar": {...}, ...}`) แล้วส่ง `--profile vendor_x.json`
  · คีย์สะกดผิด = error · ส่วนที่ไม่ได้ให้ใช้ค่าของ `serving_example` และ**ขึ้นในรายการ "not measured" เสมอ** — ไม่เคยกลายเป็นค่าของ Emma เงียบๆ
- สิ่งที่ไม่อยู่ในโปรไฟล์โดยตั้งใจ: โค้ดเดินของ Emma (board_walk) — หุ่นเสิร์ฟมีระบบนำทางของผู้ขายเอง · ห้อง/เฟอร์นิเจอร์/แท่น (อยู่ในแพ็กเกจแผนที่)

## แพ็กเกจแผนที่ (portable map package)

```
python scripts/map_package.py export --map <board .stcm | explore .bin | ROS .yaml> --out DIR
       [--truth <grid>] [--findings findings.json] [--spots <ไฟล์จุดของหุ่น | ไฟล์จากหน้ามาร์กจุด>] [--profile emma]
python scripts/map_package.py import DIR                  # อ่านกลับ + ตรวจด้วยตัว Emma
python scripts/map_package.py check DIR --profile serving_example
```

ในโฟลเดอร์:

| ไฟล์ | คืออะไร |
|---|---|
| `map.pgm` + `map.yaml` | ตารางสิ่งกีดขวางแบบ ROS `map_server` (trinary: 0 ทึบ / 254 ว่าง / 205 ไม่รู้, thresholds 0.65/0.196) — `origin` = มุมล่างซ้ายของช่องล่างซ้าย = origin ของบอร์ดเป๊ะ |
| `lidar_truth.*` (ถ้ามี) | สิ่งที่เลเซอร์ ≥ 2 รอบเห็นตรงกัน ถ้าต่างจากแผนที่ที่ใช้นำทาง |
| `glass.*` (ถ้ามี) | ช่องที่เป็นของทึบแต่เลเซอร์มองทะลุ (phantom ของ map_check = กระจก/ป้ายกระจก — **ห้ามลบ** ตามกฎชั้น 1) |
| `places.json` | แท่น (ท่า + ที่มา + approach/back_from_m), จุด (ที่มา: ไฟล์งาน / บันทึกที่หุ่น / หน้ามาร์ก), จุดที่ยังไม่มีตำแหน่ง, ทางเดินของ floor1.json, ของบนพื้น (รัศมี), เขตห้าม (`no_walk_up_below_y`), marker แท่นของบอร์ด (ค้าง) |
| `transform.json` | ผังสถาปนิก → กรอบแผนที่ (หมุน −10.8° รอบ (−9.6, −4.7) เลื่อน (−0.69, −0.10)) และสูตรกลับ |
| `preview.png` | ภาพให้คนดู: แผนที่ + ทุกอย่างข้างบน |
| `package.json` | รูปแบบ/เวอร์ชัน, กรอบพิกัด, sha256 ทุกไฟล์และทุกแหล่ง, หุ่นที่ทำแผนที่, **สิ่งที่ไม่อยู่ในแพ็กเกจ** |

กรอบพิกัด: เมตร, กรอบแผนที่ของบอร์ด (x, y เหมือน floor1.json), มุมเป็นองศาทวนเข็มจาก +x · แถวแรกของ PGM = ด้านบนของแผนที่ (y มาก)

ตัวอ่านของเราอ่านไฟล์ ROS จากที่อื่นได้: P5/P2, 8/16 บิต, comment, `negate`, `mode: scale/raw` (raw: 0..100 = ค่าความทึบ, ค่าอื่นทั้งหมด = ไม่รู้ —
map_saver ของ nav2 เขียน "ไม่รู้" เป็น 255) · สีขาว = `maxval` ในหัวไฟล์ PGM (ไม่ใช่ 255 เสมอ) · แผนที่ที่หมุน (origin yaw ≠ 0) **ปฏิเสธ** ไม่เดา
· ไฟล์ในแพ็กเกจถูกแก้หลังเขียน (sha ไม่ตรง) = error

## หุ่นเสิร์ฟจะใช้แพ็กเกจยังไง (สิ่งที่รู้ / ต้องถามผู้ขาย)

| ทาง | รู้แล้ว | ต้องถาม |
|---|---|---|
| ROS / ROS 2 (`map_server`, Nav2) | `map.yaml` + `map.pgm` โหลดได้ตรง (รูปแบบมาตรฐาน); จุด/แท่นเป็น pose ในกรอบ `map` ใช้กับ `NavigateToPose` ได้ (yaw องศา → quaternion) | หุ่นใช้ ROS ไหม เปิดให้โหลดแผนที่เองได้ไหม |

## floor_sim กับหุ่นอื่น

```
python scripts/floor_sim.py profile                                   # serving_example บนเฟอร์นิเจอร์ 16 พ.ย. + ไฟล์งาน
python scripts/floor_sim.py profile --profile vendor_x.json --spots <จุดที่มาร์ก>
python scripts/floor_sim.py profile --package .tmp/map-package/20261120-floor1
```

- ทุกจุด: ตัวพอดีไหม (จุดกว้างสุดห่างของ ≥ ช่องว่างของหุ่นนั้น), หมุนอยู่กับที่ได้ไหม, ตัววางทางของมันจะไม่รับเป็นเป้าไหม
- ทุกทางระหว่างจุด: เดินเป็นท่อน MoveTo ด้วยตัว/เลเซอร์/ความเร็วของหุ่นนั้น — ตัดของเฉพาะ Emma ออก (creep, forward, back_to, หมุน, แท่น) ทางกลับแท่น = ไปจุด approach
  (หุ่นเสิร์ฟเข้าแท่นเอง) · เริ่มจากแท่น = เริ่มที่จุด approach
- **ดูที่ความสูงถาด:** จุดที่ตัวเข้าใกล้ของ (ที่ระนาบเลเซอร์) < 0.30 ม. — ถ้าของนั้นเป็นโต๊ะ/เคาน์เตอร์ หน้าโต๊ะยื่นเกินขา
- พื้นที่ล็อบบี้ที่หุ่นนั้นอยู่/หมุนได้ เทียบกับ Emma
- **ที่มันไม่บอก:** แผนที่และเฟอร์นิเจอร์คือสิ่งที่**เลเซอร์ของ Emma** เห็นที่ระนาบของมัน (ความสูงยังไม่เคยวัด) · หน้าโต๊ะ/ความสูงถาดไม่มีในแผนที่ไหนเลย ·
  ระบบนำทาง/หาตำแหน่ง/เข้าแท่นของผู้ขายไม่ได้จำลอง (ใช้โมเดลตัววางทางของตัวจำลอง) · โต๊ะ 1–6 ยังไม่มีตำแหน่ง
