# ลองให้ Emma ฟังเสียงคนเดียว ด้วยไมค์ GCK บนคอม (19 พ.ย. 2026)

เจ้าของ: *"แยกเอเจนท์มาทำเรื่องเสียงในคอมก่อนให้จำเสียงคนคนเดียว โดยเราจะลองก่อนว่าได้ไหม ตอนนี้ที่คอมติดไมค์กับที่จะใช้กับหุ่นแล้ว"*
แล้ว *"ทำเป็นที่ให้พูดเพื่อบันทึกเสียงหน่อย เพราะจะให้ไมค์มันจับแค่เสียงคนนั้น ทำระบบแล้วเช็คด้วย"*

รอบ 5 พ.ย. (ล็อกเสียงที่ถอดออกไป) ฟังผ่านอาร์เรย์ของหุ่น — คนเดียวกันต่างสายได้คะแนน 0.43–0.72 และคำสั้นของเจ้าของถูกทิ้ง ·
รอบนี้เปลี่ยนไมค์ (ไมค์ไร้สายติดตัว) แล้ววัดว่าแยกคนได้ไหม · **ยังไม่ขึ้นหุ่น ไม่แตะ robot.env**

## ทางหลัก: หน้าเว็บ `/voice-lock` (ไม่ต้องใช้ terminal)

1. เปิดเซิร์ฟเวอร์ Emma บนคอมตามปกติ (ถ้าเปิดอยู่ก่อนแก้นี้ ต้องปิดแล้วเปิดใหม่ หน้าใหม่จึงจะมี)
2. บนคอมที่เสียบตัวรับไมค์ เปิด **https://127.0.0.1:8001/voice-lock** (หรือ localhost — เครื่องนี้ไม่ต้องใส่ token; เครื่องอื่นต้อง `?token=...`)
3. ทำตามข้อ 1–5 บนหน้า: **เปิดไมค์** (เลือก GCK ให้เอง แถบบอกว่า ได้ยินดี / เบามาก / ดังเกิน / **ไม่มีเสียงเลย = ศูนย์ล้วน ตัวส่งปิด**) →
   **บันทึกเสียง 40 วิ** (ติ๊กยินยอม อ่านข้อความบนจอ — บอกผลว่าพูดพอไหม มีเสียงอื่นปนไหม) → **ลองฟัง** ปุ่ม "ฉันพูด" / "อีกคนพูดใส่ไมค์ตัวนี้" /
   "คนข้างๆ พูด ไม่มีไมค์" (แต่ละประโยคขึ้น ✓ ใช่เสียงนี้ / ✗ ไม่ใช่ พร้อมคะแนนและความยาว + รายการ 20 ประโยคให้อ่าน) → **สรุปผล** (ได้ / ไม่ได้ / ยังบอกไม่ได้ + ตัวเลข) → **ลบ**
4. หน้าใช้โค้ดเดียวกับสคริปต์ข้างล่าง (`app/one_voice.py`) ข้อมูลอยู่ที่เดียวกัน (`data\voice-lock\`) จะสลับใช้ก็ได้
5. ไมค์ในหน้าผ่านการประมวลผลของเบราว์เซอร์แบบเดียวกับสายคุยจริงของเครื่องนี้ (ตัดเสียงสะท้อน + ลดเสียงรบกวน/ปรับระดับตาม .env) — ลายเสียงที่ได้ฟังแบบเดียวกับสาย

## ประตูเสียงในสายจริง (`ONE_VOICE_PROFILES`, ปิดเป็นค่าเริ่ม — ยังไม่เปิดที่ไหน)

เมื่อผลขั้นทดสอบ "ได้" แล้วอยากให้ Emma ฟังแค่คนนี้จริง: ใส่ใน `.env` ของคอม เช่น `ONE_VOICE_PROFILES=condo` (+ `ONE_VOICE_NAME=owner` ถ้ามีหลายคน,
`ONE_VOICE_THRESHOLD=` ตามที่หน้าแนะนำ) แล้วเปิดเซิร์ฟเวอร์ใหม่ · ว่าง = ทุกโปรไฟล์ทำงานเหมือนเดิมทุกไบต์ (มีเทสต์) · **ไม่ได้ใส่ใน robot.env**

กติกา (ตัดสินจากที่วัด — `app/one_voice.py`):

- **ประโยค (เสียงพูด ≥ 1.2 วิ) ตัดสินด้วยลายเสียง** — ถือหัวประโยคไว้ 1.2 วิ ไม่ส่งไปไหน ผ่านแล้วส่งทั้งประโยคตามลำดับ (ไม่หาย) ไม่ผ่าน = ไม่ส่งอะไรเลย ·
  ต้องดังไม่ต่ำกว่าระดับของคนติดไมค์เกิน 15 dB ด้วย (ไมค์ติดตัวได้ยินคนข้างๆ เบากว่ามาก)
- **คำสั้น (< 1.2 วิ) ตัดสินด้วยความดังอย่างเดียว** ผ่านถ้าไม่เบากว่าประโยคที่ผ่านล่าสุดของคนนั้นเกิน 8 dB · ไม่มีช่วงเวลา "ปล่อยทุกเสียง" แบบ `reply_burst` 5 พ.ย.
- **ความเสี่ยงที่รู้และยอม:** ใครก็ตามที่พูดใส่ไมค์ตัวเดียวกันในระยะเดียวกัน คำสั้นของเขาผ่าน (ลายเสียงแยกคำสั้นไม่ได้) · AGC (โปรไฟล์ฟังไกลบนหุ่น) ทำให้ช่องว่างความดังแคบลง ·
  ประโยคแรกช้าขึ้นราว 1.2 วิก่อนส่ง (คำตอบไม่ช้าลงสำหรับประโยคยาวกว่านั้น) และการพูดแทรก Emma รอคำตัดสิน
- **หุ่นเดิน/ทำท่า = ทุกเสียงผ่าน** ("หยุด" ของใครก็ได้) · **ความล้มเหลวเปิดประตู** (หุ่นหูหนวกแย่กว่า) และเขียน log เตือน: โมเดล/ลายเสียงหาย, โมเดลพัง,
  คำตัดสินไม่กลับมาใน 1.5 วิหลังถาม, หรือสายนั้นไม่มีด่าน VAD ในเครื่องให้ประตูเกาะ (`VAD_MODE` ไม่ใช่ `local` — ค่าเริ่มคือ `gemini`; ไม่มีโมเดล Silero; โหมดออฟไลน์)
  → turnlog `one_voice_off` และหน้า `/voice-lock` ขึ้นแถบแดงว่า "ประตูเสียงต่อกับสายคุยไม่ได้" · **ไม่ใช่ความล้มเหลว:** ช่วงพูดที่ยาว 3 วิ (ไม่นับ pre-roll)
  แต่ดังพอไม่ถึง 1.2 วิ (เสียงพึมพำ) ตัดสินด้วยความดังแบบคำสั้น จึงถูกปฏิเสธได้
- **ต้องตั้ง `VAD_MODE=local`** คู่กับ `ONE_VOICE_PROFILES` ไม่งั้นประตูไม่มีที่เกาะ (ทุกเสียงผ่าน)
- turnlog แถว `one_voice`: decision / why / score / ความยาว / ระดับ dB เท่านั้น ไม่มีเสียง ไม่มีชื่อ
- **ทดลองผ่านประตูจริงด้วยเสียงจริง (Silero + CAM++ ตัวจริง, LibriSpeech จัดแบบการทดสอบ, คนที่สอง = คนเสียงใกล้ที่สุดในชุด):**

  | เกณฑ์ | คนที่บันทึก ประโยคผ่าน | คนที่สอง ประโยคผ่าน | คนข้างๆ (−25 dB) ผ่าน | คำสั้น: เจ้าตัว / คนที่สอง |
  |---|---|---|---|---|
  | 0.45 | 20/20 | 3/20 | 0/20 | 3/4 / 2/3 |
  | 0.50 | 19/20 | 1/20 | 0/20 | 3/4 / 2/3 |
  | 0.55 | 17/20 | 1/20 | 0/20 | 3/4 / 2/3 |

  ก่อนเพิ่มเงื่อนไข "ดูซ้ำต้องเกินเกณฑ์ 0.10" + "ดังพอ": คนที่สองผ่าน 4/20 (3 จากการดูซ้ำ) คนข้างๆ ผ่าน 3/20 · ทั้งหมดนี้ไม่ใช่ไมค์ GCK และไม่ใช่ภาษาไทย

## ก่อนเริ่ม

- ตัวรับ GCK บนคอมนี้ชื่อ **"Microphone (GCK)"** สคริปต์และหน้า `/voice-lock` เลือกให้เอง (WASAPI 48 kHz)
- **"Microphone (LCS_USB_AUDIO)" (USB 0a67:8524) ไม่ใช่ GCK** — 19 พ.ย. เดาผิดว่าเป็น GCK แล้ววัดได้ศูนย์ล้วนจึงสรุปว่า "ตัวส่งปิด" ·
  20 พ.ย. เจ้าของพูดใส่ GCK: "Microphone (GCK)" peak 0.43–0.80 rms 0.05–0.10 ขณะที่ LCS_USB_AUDIO ยังศูนย์ล้วนทุก API
- noise gate ของ GCK ส่งศูนย์ตอนไม่มีใครพูด (บนหุ่น 11 พ.ย. เงียบ = ศูนย์ 46%) → **ขั้น 0 ต้องพูดใส่ไมค์ระหว่างวัด**
- ไมค์ติดตัวตำแหน่งเดียวกับที่จะใช้จริง · ห้องปกติ (มีเสียงแอร์/คนได้) · ใช้เวลา ~10–15 นาที
- เสียงที่อัดคือข้อมูลส่วนบุคคล: ขอคนที่ร่วมทดสอบก่อน · ทุกอย่างอยู่ใน `data\voice-lock\` (gitignore) · จบแล้วลบ (ขั้น 6)

## 5 — สรุปผล (1 นาที)

```powershell
.venv\Scripts\python.exe -X utf8 scripts\voice_lock_try.py eval data\voice-lock\utterances --name owner
```

อ่าน 3 บรรทัด:

| บรรทัด | "ได้" | "ไม่ได้" |
|---|---|---|
| `VERDICT for sentences >= 1 s` | **WORKS**: มีคะแนนกั้นที่เจ้าของถูกปฏิเสธ ≤ 10% และคนที่สองผ่าน ≤ 5% | **DOES NOT WORK** = ไมค์ตัวนี้ + ห้องนี้แยกคนไม่ออก อย่าฝืนลดเกณฑ์ |
| `Short words` | `usable` (ไม่คาดว่าจะได้) | `NOT usable` = คำสั้นบอกไม่ได้ว่าใครพูด (คาดไว้แล้ว ดูข้อเสนอข้างล่าง) |
| `Level alone` | คนข้างๆ ผ่าน ~0% = ไมค์ติดตัวกันคนรอบข้างด้วยความดังได้อยู่แล้ว | คนข้างๆ ดังเท่าเจ้าของ = ต้องพึ่งลายเสียง |

- 20 ประโยคได้ผล **PROVISIONAL** เสมอ (14 ประโยคยาวที่ไม่มีใครผ่านยังแปลว่าของจริงอาจถึง ~19%) — ถ้ารอบแรก WORKS ให้ทำขั้น 2–5 อีกวัน (ไม่ต้องลงเสียงใหม่) ตัวเลขจะชัดขึ้น
- เกณฑ์ที่ eval แนะนำ ใช้กับ `listen --threshold <ค่า>` ได้ · เผื่อขึ้นไปอีก ~0.05: คนที่สองในการทดสอบคือ*หนึ่งคน* คนอื่นในงานอาจเสียงใกล้กว่า
- ส่งผลให้ผมได้: เพิ่ม `--json data\voice-lock\eval.json` (ตัวเลขล้วน ไม่มีเสียง ไม่มีลายเสียง)

## ที่วัดได้แล้วโดยไม่มีคน (ไม่ใช่หลักฐานของไมค์ GCK)

`bench` บน Mini LibriSpeech (อังกฤษ 26 คน อ่านหนังสือ ไมค์ของใครของมัน) ลงเสียง 30 วิ — ปฏิเสธเจ้าตัว / คนอื่นผ่านเฉลี่ย / **คนที่เสียงใกล้ที่สุดหนึ่งคน**ผ่าน:

| ความยาว | เกณฑ์ 0.40 | 0.50 | 0.60 |
|---|---|---|---|
| 2 วิ | 0% / 1.1% / 62% | 1.0% / 0% / 14% | 6.2% / 0% / 0% |
| 1.2 วิ | 0.7% / 1.2% / 55% | 5.9% / 0.1% / 18% | 19.9% / 0% / 4% |
| 0.5 วิ (คำสั้น) | 28% / 0.5% / 36% | 54% / 0.1% / 12% | 84% / 0% / 0% |

- **ค่าเฉลี่ยหลอก**: คนอื่นผ่าน 1% ฟังดูดี แต่คู่ที่เสียงใกล้กันที่สุดได้คะแนน 0.40–0.47 ต่อกัน ที่เกณฑ์ 0.40 คนนั้นผ่านเกินครึ่ง — ล็อกเสียงเจอคนเดียวคือคนนั้น จึงตั้งค่าเริ่มที่ 0.50
- ทดสอบครบทางด้วยไฟล์ LibriSpeech จัดแบบขั้น 2–5 (คนที่สอง = คนที่เสียงใกล้ที่สุดในชุด, nearby = คนเดียวกันเบาลง 25 dB ที่ผมสร้างเอง): ประโยค ≥ 1 วิ WORKS ที่ 0.54 (เจ้าตัวถูกปฏิเสธ 1/20, อีกคนผ่าน 1/20) · คำสั้น EER 29% ใช้ไม่ได้
- ทุกคนในชุดนี้มีไมค์/ห้องของตัวเอง ซึ่ง**ช่วย**โมเดล · สองคนพูดใส่ไมค์ GCK ตัวเดียวได้คะแนนใกล้กันกว่านี้เท่านั้น · ไม่มีชุดเสียงไทยหลายคนในเครื่อง (edge-tts ตอบ 403, เสียง Windows มีแค่อังกฤษสองตัว) — ภาษาไทยยังไม่ได้วัดรอบนี้

## คำสั้น — ทำไมประตูเลือก "ตัดสินด้วยความดัง" (ไม่มีช่วงเวลา)

คำสั้น (< 1 วิ: ค่ะ ใช่ หยุด yes) **แยกคนด้วยลายเสียงไม่ได้** — วัดแล้วทั้งรอบ 5 พ.ย. และรอบนี้ · ประตูในสายจริงใช้ "ดังไม่ต่ำกว่าคนติดไมค์เกิน 8 dB"
(ไม่มีเงื่อนไขเวลา เพราะช่วงเวลาคือสิ่งที่ปล่อยทุกคนเข้ามาเมื่อ 5 พ.ย.) · ข้อเสนอแรกของรอบเช้าคือ:

> คำสั้นผ่านเฉพาะภายใน N วิ หลังประโยคยาวที่ ACCEPT **และ** ดังใกล้ระดับของคนติดไมค์ (±6 dB)

- **ความเสี่ยง:** 5 พ.ย. ช่วง 6 วิ (`reply_burst`) ปล่อย*ทุก*เสียงผ่าน · ข้อนี้แคบกว่าด้วยเงื่อนไขความดัง ซึ่งกันคนรอบข้างที่ไม่มีไมค์ได้ (ถ้าขั้น 4 ยืนยัน)
  แต่**กันคนที่พูดใส่ไมค์ตัวเดียวกันไม่ได้เลย** (ดังเท่ากัน) — ในการทดสอบ LibriSpeech กฎนี้ปล่อยคำสั้นของคนที่สอง 2/3
- เพิ่มเงื่อนไขคะแนน (≥ เกณฑ์−0.10) ตัดคนที่สองได้ แต่ก็ตัดคำสั้นของเจ้าตัวเกือบหมด (0/4) = กลับไปเป็นอาการ 5 พ.ย.
- `eval` พิมพ์ทั้งสองแบบ (`Short-word rules`) จากเสียงจริงของขั้น 2–4 — สมมติว่าทุกคำสั้นอยู่ในช่วงเวลา (ดีสุดสำหรับเจ้าของ แย่สุดสำหรับคนอื่น)
- **"หยุด" ห้ามผ่านด่านนี้เลย**: ระหว่างหุ่นเดิน/ทำท่าทุกเสียงต้องผ่าน (กฎ ROBOT_MOVING) ไม่ว่าใครพูด

## ยังไม่รู้จนกว่าจะวัด

- คะแนนคนที่สองบนไมค์ GCK ตัวเดียวกัน (ขั้น 3 คือตัวตัดสิน) · ภาษาไทย · noise gate ตัดหัวคำสั้นไหม · ไมค์ติดตัวขยับ/เสียงเสื้อถู
- เสียง Emma จากลำโพงเข้าไมค์ (บนหุ่น 12 พ.ย. 0.03–0.08) จะถูกนับเป็น "คนอื่น" หรือไม่ — ทดสอบตอนต่อจริง
- บนหุ่น: CPU ของโมเดลลายเสียง (PC: ~12–26 ms ต่อประโยค, RK3588 ยังไม่วัด) และ Android เลือกไมค์ GCK หลังรีบูตหรือไม่ (12/18 พ.ย. เลือกอาร์เรย์)
