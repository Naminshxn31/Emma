| ข้อ | สถานะ |
|---|---|
| 2. ทำไมต้องบริษัทไทย | ตอบจากเว็บบริษัท (บทความ Empire vs developers อื่น) — ทดสอบค้นเจอแล้ว |
| 3. ตัวเลขสิ่งอำนวยความสะดวก | สไลด์ + เว็บ (หน้า project information) |
| 4. ทำไมลงทุนคอนโด/พัทยา/โครงการเรา | บทความชุดใหญ่ในเว็บครอบคลุม *(ยกเว้นสถิติเช่า Emp/Orient + ROI → ต้องขอข้อมูล ดูข้อ 4 ในตารางรอข้อมูล)* |
| 7. ล่าม สเปน/ฝรั่งเศส/เยอรมัน/จีน/อาหรับ | **เสร็จวันนี้**: โหมดล่าม + เลือกภาษาปลายทางจาก URL เช่น `/?profile=translator&lang=es` (es/fr/de/zh/ar/ru/ja/ko...) — พนักงานพูดไทยออกเป็นภาษาลูกค้า ลูกค้าพูดอะไรกลับมาเป็นไทยเสมอ |
| 13. ข้อดี off-plan | บทความ pre-sale 5 reasons ในเว็บ — ค้นเจอแล้ว |
| 14. โปรไฟล์บริษัท | เว็บครอบคลุม Empire Group *(โครงการอื่นในเครือ → ต้องขอเอกสาร)* |
| 16. ต่อจอใหญ่ | มีอยู่แล้วสองทาง: (1) HDMI/casting จอไหนก็ได้ (2) เปิด `http://<เครื่องหลัก>:8000/display?token=<WS_TOKEN>` บนจอที่สองเป็นจอสไลด์เต็มจอ — **ต้องมี `?token=` ต่อท้าย** ถ้าเครื่องหลักตั้ง `WS_TOKEN` ไว้ (ควรตั้ง ดู README หัวข้อ LAN) ไม่งั้นจอจะขึ้นว่าต้องใส่ token |

หมายเหตุข้อ 2/3/4/13/14: เนื้อหาพวกนี้ค้นได้ผ่านคลังเว็บ 96 หน้า ตอนนี้อยู่ในโปรไฟล์ emma —

## แบบฟอร์มที่ต้องส่งให้ฝ่ายขายกรอก (ตัวปลดล็อกจริง)

**ตารางยูนิต** — Excel ก็ได้ คอลัมน์:

```
เลขห้อง | ตึก/ชั้น | แบบ (1BR/2BR) | ขนาด ตร.ม. | ทิศ/วิว | ราคา THB | สถานะ (ว่าง/จอง/ขายแล้ว) | หมายเหตุ
```

พร้อมสองช่องท้ายไฟล์: **ผู้อนุมัติราคา** และ **ใช้ได้ถึงวันที่** — เหมือน `approved_by`
ของ condo_facts เหตุผลเดียวกัน: ตัวเลขที่ไม่มีเจ้าของคือตัวเลขที่หุ่นห้ามพูด

ส่งมาแล้วผมเขียนตัว import + tool ค้น/กรอง/เทียบ ได้ใน 1-2 วัน → ปลดล็อกข้อ 1, 6, 8, 11, 15, 19 ทีเดียว

## ตรวจซ้ำกับโค้ดจริง (24 ส.ค. 2026 รอบสอง) — 4 จุดที่ตารางข้างบนยังพูดไม่ครบ

**1. ข้อ 2/3/4/13/14: เติม `TOOL_GROUPS` บรรทัดเดียวยังไม่พอจริง**
`enabled_tool_groups()` เปิดเครื่องมือให้ก็จริง แต่ prompt ของโปรไฟล์ condo
(`BASE_INSTRUCTIONS`) **ไม่เคยพูดถึง `search_my_documents` เลย** — บล็อก `[เอกสาร]`
ที่ลิสต์ชื่อไฟล์ให้โมเดลรู้ว่ามีอะไรค้นได้ ถูก replace เฉพาะใน `EMMA_INSTRUCTIONS`
(prompts.py บรรทัด 391) ส่วนกฎข้อ 14 สั่งตรงๆ ว่า "ให้เรียก `search_condo_info`
ก่อนตอบ" และกฎเหล็กบรรทัดแรกห้ามตอบนอกเรื่องทุกกรณี
คำอธิบายเครื่องมือเองก็ขึ้นต้นว่า "ค้นในเอกสาร**ของเจ้าของ**" ซึ่งอ่านแล้วไม่ใช่
งานของหุ่นห้องขาย → รูปเดิมของบั๊ก "คำสั่งท้าย prompt = ถูกเมิน":
เครื่องมือมีอยู่แต่โมเดลไม่มีเหตุให้เรียก
**ต้องแก้ prompt (แก้โค้ด ~5 บรรทัด + เทสต์) ไม่ใช่แก้ .env อย่างเดียว**

**2. และก่อนจะเปิด ต้องตัดสินใจเรื่องตัวเลขก่อน**
คลังเว็บมีตัวเลขผลตอบแทนอยู่จริงในบทความการตลาด — วัดแล้ว: "rental yields of
7-10%", "returns reaching between 5% to 8% annually" ตัวเลขพวกนี้**ไม่มี
`approved_by`** และ `_is_commercial()` ที่ดักคำถามราคาไว้ ดักอยู่ใน
`search_condo_info` เท่านั้น **ไม่ได้ดัก `search_my_documents`**
เปิด mydocs ให้ห้องขายโดยไม่แตะอะไรเลย = หุ่นพูดตัวเลข ROI ให้ลูกค้าได้
โดยไม่มีคนรับผิดชอบ ซึ่งเป็นสิ่งเดียวกับที่ `condo_facts.json` ตั้งใจกันมาตลอด
ทางเลือก: (ก) ให้ `_is_commercial` ครอบ mydocs ด้วย หรือ (ข) แยกคลังเว็บ
ชุด "อนุมัติแล้ว" ออกมาต่างหาก — ต้องเลือกก่อนเปิด

**3. ข้อ 10 Prime One — ยืนยันว่าไม่มีจริง** grep คลังเว็บ 127 ไฟล์: คำว่า
"Prime One" เจอ **0 ครั้ง** ไม่มีอะไรให้ค้นเลย ต้องขอเอกสารสถานเดียว

**4. ข้อ 4 สถิติ Orient — ที่มีในคลังไม่ใช่สิ่งที่ฝ่ายขายขอ**
"The Orient Resort & Spa" ปรากฏในฐานะ*แลนด์มาร์กใกล้โครงการ*เท่านั้น
ไม่มีสถิติค่าเช่า/อัตราเข้าพักสักบรรทัด — ตรงกับที่ตารางข้างบนเขียนไว้ว่าต้องขอ
แต่ระบุให้ชัดว่าขออะไร: **ค่าเช่าจริงรายเดือน + อัตราการปล่อยเช่าได้ ของ Empire
และ Orient ย้อนหลังอย่างน้อย 12 เดือน** ไม่ใช่ "ข้อมูลการลงทุน" ลอยๆ
