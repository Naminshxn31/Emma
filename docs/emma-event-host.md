# Emma Event — Emma เป็นเจ้าบ้านในวันงานอีเวนต์

เจ้าของ 30 ต.ค. 2026: *"ทำโหมดใหม่ แยกเป็นอีกแอป ... ให้ emma เป็น host งานคอยรับแขกในวันงานอีเว้น
... เชิญลูกค้า แล้วพาไปยังจุดต่างๆ และคอยไปทักทายคนต่างๆที่โต๊ะ ... ทำเป็นซีนๆ"*
· สถานที่: สำนักงานชั้น 1 · ทีมงานกดเปลี่ยนซีน · วันงาน 25–26 พ.ย. 2026

> ร่างแรก — บทของแต่ละฉากยังเป็นร่างของผม เจ้าของยังไม่ได้บอกว่าแต่ละฉากต้องทำ/พูดอะไร
> การเดินจากหน้าคุม**ยังไม่เคยลองบนหุ่นจริง** และปิดไว้ (`EVENT_WALK_ENABLED=false`)

## มีอะไรบ้าง

| ส่วน | อยู่ที่ |
|---|---|
| แอปบนหุ่น "Emma Event" (ไอคอนแยกจาก "Emma Robot") | สร้างจากโค้ดเดียวกัน: `gradlew assembleDebug -PemmaApp=event` → แพ็กเกจ `com.emma.robot.event` |
| Emma โหมดงาน (profile `event`) | เหมือน Emma ห้องขายทุกกฎ + บล็อกงานอีเวนต์ (`app/event_host.py`) |
| ฉาก จุด และข้อมูลงาน | `data/events/floor1_event.json` (แก้ได้เลย) |
| หน้าคุมบนมือถือทีมงาน | `http://<ip หุ่น>:8003/event-control?key=...` (`app/event_control_server.py`) |
| การเดิน | เซิร์ฟเวอร์บนหุ่นรัน `scripts/board_walk.py` ตัวเดียวกับที่เดินชั้น 1 เมื่อ 28 ต.ค. (`app/event_walk.py`) |

แอปเดิม "Emma Robot" ไม่เปลี่ยน — build ปกติ (ไม่มี `-PemmaApp`) ได้แอปเดิมทุกอย่าง
และสองแอปเปิดพร้อมกันไม่ได้ (ไมค์/แขนใช้ได้ทีละแอป) แอปที่เปิดทีหลังจะปิดอีกแอปให้ก่อนใช้แขน

## ฉากในร่างแรก

| ฉาก | หุ่นเดินไป | Emma พูด |
|---|---|---|
| รับแขกหน้างาน | กลางส่วนต้อนรับ | ต้อนรับเข้างาน เชิญไปจุดลงทะเบียน |
| พาแขกไปห้องมัลติมีเดีย | หน้าห้องมัลติมีเดีย | ชวนเดินตาม → ถึงแล้วเชิญเข้าห้อง |
| เดินทักทายตามโต๊ะ | โต๊ะ 1 → 6 (ทีละโต๊ะ กด "ไปจุดถัดไป") | ทักทาย ขอบคุณที่มาร่วมงาน ถามหนึ่งคำถาม |
| แนะนำโครงการ | อยู่กับที่ | เล่าภาพรวมโครงการ |
| ส่งแขก | ฝั่งทางเข้า | ขอบคุณ กล่าวลา |
| กลับแท่นชาร์จ | แท่นชาร์จ | ขอตัวไปชาร์จแบต |

กดฉาก = หุ่นเดินไปจุดของฉาก (ถ้าเปิดการเดินและบันทึกจุดแล้ว) Emma พูดประโยคเริ่มฉาก
แล้วพูดอีกครั้งเมื่อเดินถึง · ถ้าเดินไม่ได้ (ปิดอยู่/ยังไม่บันทึกจุด) Emma เล่นฉากอยู่กับที่
และถูกสั่งไม่ให้บอกว่ากำลังเดินไป

**แขกสั่งให้หุ่นเดินไม่ได้** — โหมดงานไม่เห็นเครื่องมือเดินเลย ถ้าแขกขอให้พาไปไหน Emma จะบอกว่า
ให้ทีมงานช่วยพา · ข้อมูลงาน (กำหนดการ ของที่ระลึก ฯลฯ) Emma พูดได้เฉพาะบรรทัดใน `facts_th`
ของไฟล์งาน — ตอนนี้ว่าง = ส่งต่อทีมงานที่จุดลงทะเบียน ไม่แต่ง

## ทางหยุด (ทุกทางทำงานพร้อมกัน)

1. ปุ่ม **E-stop บนตัวหุ่น** — ทางที่เชื่อได้ที่สุด
2. ปุ่ม **หยุด** สีแดงด้านล่างหน้าคุม
3. แขก/ทีมงานพูด "หยุด" กับ Emma
4. **หน้าคุมขาดการติดต่อเกิน 5 วินาที → หุ่นหยุดเอง** (ล็อกจอ ปิดหน้า Wi-Fi หลุด) —
   ระหว่างหุ่นเดินต้องเปิดหน้าคุมค้างไว้
5. แอป Emma Event บนหุ่นปิด/หลุดเกิน 3 วินาที → หุ่นหยุดเอง
6. กดหยุดจากหน้าคุมหุ่นบน PC (`/mapview`)

## เตรียมก่อนวันงาน (ต้องทำที่สถานที่จริง)

1. **จัดโต๊ะให้เสร็จก่อน แล้วค่อยทำแผนที่ชั้น 1 ใหม่** — หุ่นวางทางจากแผนที่ ถ้าย้ายโต๊ะหลังทำแผนที่
   หุ่นจะเดินตามแผนที่เก่า (และห้าม `--map` ตอนมีคนในห้อง — คนกับบานประตูถูกบันทึกค้าง เกิดแล้ว 28 ต.ค.)
   · **ทางที่ไม่ต้องเคลียร์ห้อง:** เดินเส้นทางงาน ≥ 2 รอบ (ดีที่สุด 4) แบบ mapping ปิด โดยเปิด `WALK_FRAMES` → ดึงมาด้วย
   `python scripts/walk_frames.py pull --last` ทีละรอบ → `python scripts/map_check.py --last 4` → ดู `report.png` (แดง = แผนที่มีแต่ไม่มีจริง,
   น้ำเงิน = โต๊ะ/ของที่แผนที่ยังไม่มี, ม่วง = กระจก/ผนังวาดคลาด ไม่ลบเอง) กับ `pictures.jpg` (แต่ละจุดในภาพกล้อง) ·
   อันไหนเป็นคน/ของที่จะย้าย ใส่ `--keep เลข` แล้วรันซ้ำ · บรรทัด "self-check" ต้องขึ้น (เลเซอร์ตรงแผนที่ใหม่ดีกว่าเดิม)
   · อัป `clean.stcm` ขึ้นบอร์ด = ขั้นแยก ทำเมื่อเจ้าของสั่ง: หุ่นอยู่บนแท่น, สำรองแผนที่เดิมก่อน (`GET maps/stcm`), อัปแล้วตั้งตำแหน่งที่แท่น,
     ลองเดินก่อนแล้วค่อย `:save`
   · ถ้า summary บอกว่าข้ามเฟรมเยอะ (เลเซอร์ตรงแผนที่ < 0.40) = ห้องเปลี่ยนมากจนบอร์ดหาตำแหน่งไม่ได้ → ต้องสแกนใหม่ตอนห้องว่างจริงๆ
2. ขับหุ่นไปยืนที่โต๊ะแต่ละตัว หันหน้าตามที่ต้องการ แล้วกด "บันทึกตำแหน่งตอนนี้" ในหน้าคุม
   (กดสองครั้ง) — บันทึกลง `data/events/floor1_event.spots.json` บนหุ่น · deploy ไม่ทับไฟล์นี้
   · หุ่นยังหาตำแหน่งตัวเองไม่ได้ (Q < 50) = บันทึกไม่ได้
3. ลองเดินแต่ละจุดด้วย "ไปที่นี่" ให้ถึงสะอาดอย่างน้อย 2 ครั้ง (หน้าคุมนับให้) —
   ระวังแขนชนขอบโต๊ะ และล้อเก้าอี้ที่อยู่ต่ำกว่าระดับเลเซอร์ (เจอแล้ว 28 ต.ค.)
   · หุ่นเก็บภาพกล้องหัว + ระยะไลดาร์ทุกวินาทีระหว่างเดิน (`WALK_FRAMES`) — หลังลองเดินดูด้วย
   `python scripts/walk_frames.py pull --last` ว่าผ่านใกล้อะไรตรงไหน · ทางเดินของหุ่นควรกว้าง ≥ 1.2 ม. (หุ่นกว้าง 0.70 ม. รวมแขน 0.78)
4. เช็คเน็ตที่จุดจัดงาน — Emma ต้องใช้เน็ตตลอด ควรมีเราเตอร์ 4G สำรอง

## ติดตั้ง (ทำครั้งเดียว)

```
# 1) key ของหน้าคุม: บรรทัด EVENT_CONTROL_KEY=<สุ่มยาวๆ> ใน .env ของ PC แล้ว
python scripts/robot_server.py secrets
python scripts/robot_server.py deploy          # ส่ง board_walk + floor1.json + ไฟล์งาน
# 2) แอป: build -PemmaApp=event แล้วลงคู่กับแอปเดิม
adb install -r -g .tmp/apk/emma-event-20261030.apk
adb shell am start -n com.emma.robot.event/com.emma.robot.control.MainActivity \
    --es server_url https://127.0.0.1:8001 --es ws_token <WS_TOKEN>
# 3) เปิดการเดินเมื่อหุ่นอยู่ในตำแหน่งแล้ว: EVENT_WALK_ENABLED=true ใน data/robot-server/robot.env
python scripts/robot_server.py secrets && python scripts/robot_server.py restart
```

แอปใหม่เริ่มจากค่าว่างทั้งหมด (server, token, สวิตช์ท่าทาง, ท่าแขนที่บันทึกในสตูดิโอ) — ต้องตั้งใหม่ในแอปนี้

## ที่ยังไม่รู้ / รอเจ้าของ

- แต่ละฉากต้องทำ/พูดอะไรจริงๆ และมีฉากอื่นอีกไหม
- ชื่องาน กำหนดการ ข้อมูลที่ Emma พูดได้ (`name_th`, `facts_th`)
- Emma ตอบเรื่องโครงการด้วยไหม (ตอนนี้ตอบได้เหมือนห้องขาย) หรือพูดแค่เรื่องงาน
- จำนวนโต๊ะและตำแหน่ง
- เปิดไฟจากหน้าคุม (เจ้าของ 30 ต.ค. "หน้าควบคุมอาจจะมีเปิดไฟ"): ไฟชุดไหน เปิดปิดด้วยอะไรอยู่ตอนนี้ — ระบบมี `set_lights`
  ผ่านรีโมต IR (Broadlink) ของห้องขายที่ 192.168.0.x ซึ่งหุ่น (192.168.1.x) ไปไม่ถึง: ถ้าไฟชั้น 1 ใช้รีโมต IR ต้องมีกล่อง IR ในวงเดียวกับหุ่นแล้วสอนรหัสใหม่
  · เจ้าของ 30 ต.ค.: ระบบคุมไฟ "ยังไม่ได้ทำ" — รอฮาร์ดแวร์ก่อน

**ตัดสินแล้ว:** ภาษาเริ่มต้นในงาน = อังกฤษ (เจ้าของ 30 ต.ค.) — คือกฎเดิม: ยังไม่มีใครคุย Emma พูดฉากเป็นอังกฤษ
ประโยคแรกของแขกกำหนดภาษา และมีเมนูภาษาบนจอ (วัดสด 30 ต.ค.: ฉากก่อนมีคนคุยออกมาเป็นอังกฤษ)

## ข้อจำกัดที่รู้

- หน้าคุมเป็น http ธรรมดาบน Wi-Fi สำนักงาน (แบบเดียวกับจอห้อง `/mirror`): คนในเครือข่ายเดียวกันที่ดักคุกกี้ได้
  ก็กดฉากได้ — ทางหยุดทุกทางยังใช้ได้เสมอ
- ระหว่างหุ่นเดิน ถ้าหน้าคุมปิด หุ่นหยุด — ตั้งใจ (ไม่มีใครดูการเดินนั้น)
- ห้องมัลติมีเดียเป็นจุดอับ Wi-Fi: หน้าคุมอาจหลุดตรงนั้นแล้วหุ่นหยุด
