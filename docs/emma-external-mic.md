# ไมค์แยกจากตัวหุ่น — ตรวจก่อนทดสอบ (10 พ.ย. 2026)

เจ้าของ: *"อาจจะใช้ไมค์แยกจากตัวหุ่น เดี๋ยวค่อยทดสอบ แต่ให้เช็คให้ละเอียด แล้วดูว่ายังขาดอะไร อันไหนที่ยังต้องปรับ"*

ไล่ทั้งทางเสียงเข้า (แอป + หน้าหุ่น) และด่านกรองเสียงฝั่งเซิร์ฟเวอร์ที่จูนไว้กับไมค์อาร์เรย์ของหุ่น · **ยังไม่เคยเสียบไมค์แยกเข้าหุ่นเลย**
(`docs/near-voice-bench.md` จำลองไมค์ถือไว้: คนถือได้ยิน 72/72 คนอื่น 0/72 — จำลองบน PC เท่านั้น)

## แก้แล้ววันนี้ (ยังไม่ขึ้นหุ่น — หุ่นออฟไลน์)

1. **แอป Emma Event / Ceremony ฟังผิดโหมดบนหุ่น (ไม่เกี่ยวกับไมค์แยก เจอระหว่างตรวจ)** — `LISTEN_FAR_PROFILES` ของหุ่นมีแค่ `joke,translator,condo`
   โปรไฟล์ `event`/`ceremony` ที่มาทีหลังไม่ได้ใส่ → สายของแอปงานเปิดด้วยพื้นเสียง 0.04 ของ PC, AGC ปิด, hold-speech เปิด
   (robot.env เขียนไว้เองว่าพื้น 0.04 ตัดเสียงจริง ~21% และ 9 พ.ย. เสียงคนที่เปิดช่วงพูดบนหุ่นอยู่ 0.021–0.043) → เติม `event,ceremony` = ฟังเหมือนแอปขาย
   (พื้น 0.02 ที่วัดแล้ว) · มีผลบนหุ่นหลัง `robot_server.py secrets` + restart
2. **log ไม่เคยบอกว่าสายใช้ไมค์ตัวไหน** (หน้าหุ่นส่งชื่ออุปกรณ์ว่างทุกครั้ง) → ทุกสายบันทึกแถว `mic_device` (ตอนไมค์ของหน้าเปิดสำเร็จ): ชื่อไมค์ที่เปิด, อัตรา/ช่อง, AGC/EC/NS ที่เบราว์เซอร์ใช้,
   และชื่อไมค์ทั้งหมดที่หน้าเห็น — วันทดสอบดูแถวนี้แถวเดียวรู้เลยว่า Android ใช้ตัวรับไมค์แยกหรือยังเป็นอาร์เรย์

**วัดบนหุ่นแล้ว 10 พ.ย. 11:19 (แถว `mic_device` แถวแรก, แอป Emma Event, ไมค์อาร์เรย์เดิม):** `label` **ว่าง**, 16 kHz 1 ช่อง, AGC/EC/NS เปิด
(AGC เปิด = แอปงานฟังแบบไกลแล้วหลังแก้ข้อ 1), อุปกรณ์ที่หน้าเห็น `["?", "Speakerphone"]` — **WebView บนหุ่นไม่ให้ชื่ออุปกรณ์** การเลือกไมค์แยกตามชื่อ
จึงน่าจะทำไม่ได้ (ตรงกับที่หน้าเก่าเคยเห็น) · วันทดสอบให้ดูว่าเสียบตัวรับแล้ว `inputs` มีกี่ตัว และระดับเสียงใน `mic_report` เปลี่ยนไหม

## ไมค์แยกเข้าหุ่นได้ทางไหน

| ทาง | สถานะในโค้ดตอนนี้ |
|---|---|
| **ไมค์ไร้สายแบบตัวรับ USB** (USB Audio, ไม่ต้องลงไดรเวอร์) เสียบที่หุ่น | **ทางที่แนะนำ** · หน้าหุ่นเปิด "ไมค์ค่าเริ่มต้นของ Android" ไม่มีการเลือกอุปกรณ์ — เสียบคู่กับอาร์เรย์แล้ว Android จะใช้ตัวไหน **ยังไม่รู้** (เงียบทั้งสองแบบ ไม่มี error) → ดู `mic_device` |
| ไมค์ Bluetooth | แอปไม่มีโค้ด Bluetooth (SCO) และไม่มีสิทธิ์ BLUETOOTH_CONNECT · WebView จะใช้เองไหมไม่รู้ และเสียง BT มักเป็นแบนด์แคบ — ไม่แนะนำ |
| ไมค์ที่ PC/มือถืออีกเครื่องเปิดหน้า Emma | ใช้ไม่ได้: เซิร์ฟเวอร์บนหุ่นฟังแค่ 127.0.0.1 และถ้าต่อได้ หน้าใหม่จะ**แย่งสายของหุ่น** (สายเดียว คนใหม่ชนะ) ไม่ใช่ช่วยฟัง และไม่ใช่ "หน้าหุ่น" (ท่า/หัว/เรื่องเล่าหาย) |

ถ้าเสียบตัวรับแล้ว `mic_device` ยังเป็นอาร์เรย์: (ก) ถอดสาย USB ของอาร์เรย์ Bothlent ระหว่างใช้ไมค์แยก หรือ (ข) ให้ผมเพิ่มการเลือกไมค์ตามชื่อ —
ทำได้เมื่อ `mic_device.inputs` แสดงชื่อจริงของแต่ละตัว (หน้าเก่าบน Chrome ของหุ่นเคยเห็นแค่ "Default"/"Speakerphone" — ถ้าเป็นแบบนั้นเลือกตามชื่อไม่ได้)
· ทิศเสียง (DOA) ปิดอยู่แล้ว ใช้ไมค์แยกไม่เสียอะไร

## ด่านที่จูนไว้กับไมค์หุ่น — กับไมค์ถือใกล้ปากจะเป็นอย่างไร

ค่าบนหุ่น: พื้นเสียง `VAD_MIN_RMS_FAR` 0.02 · "เสียงใกล้หุ่น" `FOCUS_NEAR_RMS` 0.06 · ทิ้งคำตอบของเสียงเบาฟังไม่ออก `NOISE_REPLY_NEAR_RMS` 0.06 ·
หัวก้มหาคน `HEAD_SEARCH_RMS` 0.06 · เสียงที่จอ `FOCUS_SCREEN_RMS` 0.03 · เรียกชื่อ `FOCUS_WAKE_THRESHOLD` 0.10 — ไมค์ถือดังกว่าเกือบทุกค่า

| เรื่อง | ผล | ต้องทำ |
|---|---|---|
| ด่าน "ต้องเห็นหน้า" (focus) | ทุกประโยคในไมค์ผ่านเป็น "เสียงใกล้" = **คนถือไมค์คือคนเดียวที่หุ่นได้ยิน** (ตรงจุดประสงค์) | — |
| คนถือไมค์พูดกับแขก ไม่ได้พูดกับ Emma (แอป Event) | เธอตอบทุกประโยค และตัวเฝ้าคำตอบ (`REPLY_STALL_S` 8) ยังเร่งให้ตอบ | พิธีกรพูดกับแขก = ใช้แอป Ceremony (ไม่ฟัง/ฟังเฉพาะเรียกชื่อ) หรือกดปิดไมค์ |
| ไอ / จับไมค์กระแทก | ดังเกินด่านทิ้งเสียงเบา → อาจถูกตอบ "ขอโทษค่ะ ช่วยพูดอีกครั้ง" | วัดวันทดสอบ |
| **หัวหุ่น** | เสียงดังแต่กล้องไม่เห็นหน้า → หัวก้ม/หันหาคนใกล้ในไลดาร์ (ไม่ถี่กว่า 20 วิ) — ไมค์ถือ = ทุกประโยคของพิธีกรที่ยืนไกล | ปิดด้วย `HEAD_SEARCH_RMS` สูงเกินจริง (เช่น 9) ตอนใช้ไมค์แยก — ถนอมเซอร์โวหัว |
| ตา/หัวตามคน | คำของพิธีกรถูกนับให้ "หน้าเดียวที่เห็นในกล้อง" (แขกที่ยืนอยู่) → ตามองแขกคนนั้นขณะพิธีกรพูด | ยอมรับ หรือปิด HEAD_FOLLOW ช่วงนั้น |
| เสียง Emma จากลำโพง/PA วนเข้าไมค์ | หน้าหุ่นไม่รับเสียงตอนเธอพูด + 350 ms หลังจบ (half-duplex) · PA หน่วง/ห้องก้องนานกว่านั้น = เธอได้ยินตัวเอง | วัดวันทดสอบ ถ้าเกิดขยายช่วงกันเสียงสะท้อน (ตอนนี้ตายตัว 350 ms ในหน้า) |
| ปิดไมค์ (ปุ่มบนจอ, ค้างถึงเช้า) | ใช้ได้กับไมค์ทุกตัว (ตัดที่เฟรม) แต่ตัวไมค์ยังเปิดจริง · กล้องทักแล้วเปิดไมค์กลับ (`MUTE_CAMERA_GREETS`) เหมือนเดิม | — |
| ตัวรับที่ตัดเสียงเป็นศูนย์ตอนเงียบ (squelch) | ปลอดภัย (`SILENCE_RMS` ไม่ป้อนความเงียบให้โมเดล) แต่ `mic_report` จะขึ้น "DIGITAL SILENCE" | อ่านให้ถูก ไม่ใช่ไมค์เสีย |
| ประตูคนใกล้ (`VOICE_NEAR_DOOR`, ตอนนี้ shadow) | ถ้าเปิดจริง จะตัดสินจากคนที่ยืนใกล้หุ่น ไม่ใช่คนถือไมค์ | ห้ามเปิดคู่กับไมค์แยก |

## วันทดสอบ (หุ่นต้องออนไลน์ มีคนอยู่ที่หุ่น)

1. `robot_server.py deploy --dry-run` → deploy → `secrets` → restart (ไม่มีสายค้าง)
2. เสียบตัวรับ → เปิดแอป → คุยหนึ่งประโยค → ดูแถว `mic_device` ล่าสุด: `label` เป็นตัวรับไหม, `inputs` เห็นกี่ตัวและชื่ออะไร
3. เปิด `CALL_DEBUG=true` ชั่วคราว (อัดเสียงสาย 3 นาทีล่าสุด — มีเสียงคน ลบหลังวัด): พูดชิดไมค์ / ถือไกลจากปาก / ไอ / คนข้างๆ คุยกัน /
   ให้ Emma พูดผ่านลำโพงที่จะใช้จริง → อ่าน `mic_report`, `vad_floor`, `focus_open` (rms) แล้วตั้งค่าตามตัวเลข ไม่ตั้งจากทฤษฎี
4. ลองทั้งแอป Event (คุยตามปกติ) และแอป Ceremony (ช่องตอบสด)
5. ตัดสินกับเจ้าของ: ใครถือไมค์, ปิดหัวก้มหา (`HEAD_SEARCH_RMS`) ไหม, ต้องขยายช่วงกันเสียงสะท้อนไหม, ต้องมีตัวเลือกไมค์ตามชื่อไหม
