## ข้อจำกัดและสถานะหลังทดสอบ

ส่ง stop ประมาณ 2 วินาทีหลัง motion API ตอบ การเพิ่ม +40 ใช้ T800 จึงอาจเดินทางครบก่อน stop แล้ว ภาพท้ายรอบนิ่งและ ACK **ยังไม่พิสูจน์ว่า stop หยุดมอเตอร์กลางทางได้** รอบ centre ใช้ T9999 และส่ง stop ก่อนครบเวลานั้น จึงไม่ถือว่าค่า last-commanded 1500 คือจุดที่ข้อต่อไปถึงจริง

เวลา t ในภาพอ้างอิงการเริ่ม subprocess ส่งคำสั่ง ไม่ใช่ timestamp รับเฟรมของบอร์ด ภาพตัดให้เห็นหุ่นและหลีกเลี่ยงจอคอม ฉากมีโต๊ะและวัตถุบางส่วน จึงไม่ใช้ภาพอ้างว่าไม่เกิดการเคลื่อนที่ใดเลยทุกจุด

ค่า `physical_motion_observed=false` ใน serial.json รุ่นก่อนหมายถึงสคริปต์อ่านสายไม่ได้ดูภาพ ไม่ควรอ่านว่าได้พิสูจน์ว่าไม่มีการขยับ แก้สคริปต์เป็น null พร้อม `visual_assessment=not performed by serial probe` ตั้งแต่รอบช่อง 11; ไม่แก้ไฟล์ดิบย้อนหลัง รายงานนี้เป็นผลตรวจภาพที่แยกต่างหาก

กล้อง virtual index 0 ให้ภาพดำสองครั้ง จึงยุติก่อนสั่งจริง จากนั้นใช้กล้องจริง index 1 ผ่าน DirectShow หลังปิด preview Camera Hub และตรวจภาพ observe ก่อนเริ่มทดสอบ กล้องถูกปล่อยหลังจบแต่ละรอบ ไม่มีการแก้ `.env` ในชุดนี้

ยังไม่ทดลองอีก 16 ช่องที่ไม่มีผังสาย ไม่จ่ายไฟรีเลย์โดยเดาคำสั่ง และยังไม่พบช่องที่ควบคุมแขน/นิ้วจริง ผลนี้ครอบคลุมช่องที่มีในหน้าทดสอบผู้ขาย ไม่ใช่การตรวจมอเตอร์ทุกตัวในหุ่น
